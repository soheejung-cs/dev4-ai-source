## 대기 시간 조회의 우선순위 (PR#8034 이후, 미머지)
- `logtb_find_current_wait_msecs (thread_p)`(log_tran_table.c:2647) 와 `pgbuf_find_current_wait_msecs (thread_p)`(page_buffer.c:16885) 는 같은 규칙: `thread_p->wait_msecs_override != LK_WAIT_NOT_OVERRIDDEN(-3)` 이면 그것, 아니면 `tdes->wait_msecs`. 두 함수는 **복제**(pgbuf 쪽은 tdes NULL 이면 조용히 0, logtb 쪽은 `logtb_find_wait_msecs` 를 거쳐 `assert(false); return 0`). release 반환값 동일. pgbuf 쪽 위 TODO "not log_impl.h" 는 스테일(PR 이 log_impl.h 에 넣음). — 리뷰 지적 6
- override 설치 7곳: bestspace `shard::L1_fix`(-2) · `btree_set_error`(-2, vacuum 제외) · disk_manager `disk_get_volheader_internal`·`disk_stab_cursor_fix`(`pgbuf_force_latch_wait`: 0/-2 만 -1 로, 유한·-1 은 그 값을 **그대로 스레드에 복사**) · `disk_is_page_sector_reserved_with_debug_crash`(-1) · `heap_does_exist`(-1) · `log_rollback`(-1). 전부 자기 함수 안에서 복원, 중첩은 LIFO 로 정확. `log_rollback` 의 `log_zip_alloc` 실패 조기 return 은 `logpb_fatal_error(…, true, …)` 가 exit/abort 라 누수 아님.
- TDES 에 남긴 자리(의도): 문장 LOCK_TIMEOUT 힌트(query_executor.c 16117~17011), `btree_load.c:7338` 온라인 인덱스 락 승격, compactdb, lock dump(lock_manager.c:9029). 그리고 **`lock_object_wait_msecs`(6795~6807)·`lock_initialize_composite_lock`(9132)** 도 TDES — 전자는 인자가 override 에 가려지고 후자는 스냅샷. 현재 도달 경로 없음(호출자 compactdb_sr.c:566/627, locator_sr.c:11959 가 override 창 밖). **[잠재, 미수정]** — 리뷰 지적 2
- `retire_context ()`(thread_entry_task.cpp:75) 가 -3 으로 리셋, 생성자도 -3. "override 세운 채 워커를 띄우지 않는다" 불변식은 **코드 강제 없음** — 리뷰 지적 4(claim 경로 assert 제안).

## 교착 탐지기와 TDES
- victim 선정 3곳(lock_manager.c:5249, 5325, 8634)은 `LK_CAN_TIMEOUT (logtb_find_wait_msecs (t))` 로 **TDES 만** 읽는다. override 로 대기 중인 락 요청의 실제 대기 시간은 보지 못함.
- `log_rollback` 의 두 호출자(log_manager.c:4135 sysop abort, 5362 `log_abort_local`)는 직전에 `tdes->state = TRAN_UNACTIVE_ABORTED`; victim 루프는 `logtb_is_active (tranid) == false` 를 건너뜀(8644) → 롤백 중 트랜잭션은 override 와 무관하게 victim 아님. 나머지 6곳 창은 래치만.
