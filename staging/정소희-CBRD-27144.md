# 정소희 — CBRD-27144 (세션 변수 술어의 선택도 추정) 환류 대기

작성: 정소희 (.50) · 기준 리비전 upstream/develop `604ab8b22`·`582fa3941` · 2026-10-30, 11-03 갱신
상태: 아래 1~4 는 develop 의 사실이라 바로 modules 로 옮겨도 된다. **미수정** — 수정 PR#8344 는 2026-11-02 미머지로 닫혔다(JIRA Won't Do, 백로그: 세션 변수는 실사용이 드물어 플랜 변화 리그레션 위험이 이득보다 크다는 리뷰어 판단). 그 PR 의 코드 사실(옛 5항)은 옮기지 않는다.

1. **[src-compat §2] `EXECUTE … USING @v` 의 세션 변수는 EXECUTE 때 값으로 풀려 bind 값이 된다 — 첫 EXECUTE 피킹이 상수 USING 과 똑같이 걸린다** (.50, develop `604ab8b22` release CS 실측, 2026-10-30).
   - 풀리는 자리: `values_list_to_values_array ()` (db_vdb.c, 2014년부터 같음)가 PT_EVALUATE_VARIABLE 원소를 `db_get_variable ()` 로 꺼내 값 배열에 복제하고, `do_set_user_host_variables ()` 가 `db_push_values ()` 로 넣는다.
   - 실측(10만 행, 표마다 텍스트를 select 식으로 갈랐다): 값 0 은 TABLE fetch 938. 값 99990 은 PREPARE 플랜이 TABLE 이었다가 EXECUTE 때 재플랜해 INDEX fetch 12.
   - CBRD-27144 원래 본문의 "USING 의 세션 변수는 폴백"은 맞지 않았다.

2. **[src-optimizer §3] 질의 본문의 세션 변수 술어(`c1 > @v`, `c1 = @v`)는 develop 에서 기본 선택도로 추정된다(범위 0.1, 등호 1/NDV)** — 고치지 않기로 했다: PR#8344 는 닫혔다(11-02, Won't Do) (.50, develop `604ab8b22` 실측, 2026-10-30).
   - 원인: `qo_classify ()` 가 PT_EXPR(PT_EVALUATE_VARIABLE) 를 PC_OTHER 로 분류하고, 히스토그램 탐침은 PC_CONST·PC_HOST_VAR 의 값만 쓴다.
   - 예: 10만 행에서 `set @v = 0; … c1 > @v` 는 sel 0.1 → INDEX, fetch 100193. 같은 값의 리터럴은 TABLE, fetch 938.
   - 옵티마이저에 도착하는 꼴:
     - `>`·`<`·BETWEEN·IN·OR·LEFT JOIN ON 은 재작성에서 RANGE 가 된다. `@v < c1` 도 뒤집혀 RANGE 다. 이 꼴은 `qo_between_range_arg_value ()` 를 탄다.
     - 단일 `=`·`<>` 는 `qo_equal_selectivity ()` 를 탄다.
     - NOT IN(원소 둘 이상)은 `qo_all_some_in_selectivity ()` 의 PC_OTHER 경로로 가서 기본값이다.

3. **[src-query §2 / src-optimizer §2] 스캔 식에 세션 변수 읽기가 있으면 병렬 스캔을 하지 않는다** (.50, develop `582fa3941` 소스 + 100만 행 실측, 2026-10-30).
   - 서버: `px_scan_checker.cpp:371` 이 T_EVALUATE_VARIABLE·T_DEFINE_VARIABLE 에 CANNOT_PARALLEL_SCAN 을 세운다. 주석이 클라이언트 `qo_check_serial_block_expr ()` 와 짝임을 밝힌다.
   - 실측: 인덱스 1095쪽에서 `count(*) … c1 > @v` 는 직렬이고, 같은 모양의 리터럴은 parallel workers 4 다.
   - 따라서 옵티마이저가 그 항을 히스토그램으로 추정해 `QO_TERM_SEL_FROM_HISTOGRAM` 을 세워도, 실제 병렬로 가지 않는다.

4. **[src-compat §2 / src-session] 세션 변수는 DATE·DATETIME 값을 문자열로 보관한다** (.50, develop `582fa3941` 실측, 2026-10-30).
   - `set @d = date'2022-09-20'` 뒤 `typeof(@d)` 는 `character varying (1073741823)` 이다.
   - 그래서 날짜 열 술어는 타입 검사가 `cast(@d as date)` 로 감싸고, 옵티마이저에는 맨 세션 변수 읽기가 아니라 cast 식으로 도착한다.
   - 문자열 값과 INT 열(`a = @v`, @v = '1')은 cast 없이 맨 읽기로 남는다. 이 경우 히스토그램이 키 종류 불일치로 기본값에 남는다(histogram_cl.cpp:1207).
