- **[query §3 / optimizer §3] UPDATE STATISTICS 편승의 성립 조건은 chn 단독이 아니다** (.51, `66bfd071d`, 2026-09-17): `do_update_stats`(execute_statement.c ~4955~4985)는 `stats_fresh && !drop_histogram && !no_histogram && bucket_count <= 0 && !random_seed && (!with_fullscan || stored_fullscan) && histograms_rebuilt` 을 AND 로 요구한다. `stats_fresh`(= `_db_class` 행 chn 변화, `xstats_enter_update_gate`)는 "남이 커밋했다"는 **필요조건**일 뿐이고 옵션 검사는 chn 과 독립이다 — `BUCKETS n`·`RANDOM SEED` 는 chn 이 변했어도 항상 직접 수집하고, `WITH FULLSCAN` 은 `_db_class.statistics_strategy`(gate 가 `stored_fullscan` 으로 돌려줌)가 fullscan 일 때만 편승한다. `bucket_count` 는 `WITH n BUCKETS` 미지정 시 0 (parse_tree.h 3071). **미수정**
- **[storage §2] `_db_histogram` 카탈로그 컬럼에 버킷 수가 없다** (.51, `66bfd071d`, 2026-09-17): `system_catalog_initializer::get_histogram`(schema_system_catalog_install.cpp 1240~1265)의 컬럼은 `class_of`(object) · `key_attr`(varchar 255) · `with_fullscan`(integer) · `null_frequency`(double) · `histogram_values`(varbit) 다섯과 `(class_of, key_attr)` UNIQUE 뿐이다. 버킷 수는 `histogram_values` 블롭 안에만 있고 부기 컬럼이 없다 → 편승 판정이 버킷 수를 대조할 수 없다(기본 버킷 요청이 타 세션의 `WITH n BUCKETS` 결과를 물려받는 한 방향 구멍). per-column fullscan 은 `_db_histogram.with_fullscan` 에, per-class 는 `_db_class.statistics_strategy` 에 따로 있다. **미수정**
- **[transaction §3] 게이트 대기는 lock_timeout 기본 무제한이다** (.51, `66bfd071d`, 2026-09-17): `PRM_ID_LK_TIMEOUT_SECS`·`PRM_ID_LK_TIMEOUT` 기본값이 `-1 /* Infinite */`(system_parameter.c 1340~1360)이고 `catcls_lock_class_stats_gate` 는 `LK_UNCOND_LOCK` 으로 잡으므로, 오토커밋 OFF 홀더가 미커밋인 동안 같은 클래스의 통계 수집 대기는 서버 쪽에서 끊기지 않는다(실측 30초 이상, 클라이언트에서 끊음). 반면 같은 테이블의 SELECT·INSERT·`SHOW INDEXES`·`/*+ RECOMPILE */` 컴파일·다른 테이블 통계는 0.02~0.03초로 통과한다 — `_db_class` 가 카탈로그 클래스라 읽기가 NULL_LOCK 이기 때문. **미수정**
