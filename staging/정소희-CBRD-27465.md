# staging — 정소희 · CBRD-27465 (PR#7991 semi/anti 조기 종료)

작성: 정소희(.51) · 기준 리비전 `CBRD-27251` 로컬 트리 + PR#7991 head · 2026-09-22

- **[src-query §2] `QPROC_SINGLE_INNER` 게이트는 배치를 다 읽은 뒤에야 듣는다** (.51, PR#7991 head, 2026-09-22):
  PR#7991 의 코드 주석이 명시한다 — "the join-level first-match gate (QPROC_SINGLE_INNER) **does not stop the
  btree**: it only stops **re-entry after the batch is read**". 인덱스 접근은 `scan_get_index_oidset()` 이
  OID 배치를 채우고 `curr_oidp` 로 훑으므로 `next_scan` 1회가 이미 배치 하나를 읽는다. **미수정 아님 — PR#7991 이 이 지점을 고친다.**
- **[src-query §2] 힙(순차) inner 는 게이트만으로 끊긴다** (.51, `CBRD-27251`, 2026-09-22):
  `S_HEAP_SCAN → scan_next_heap_scan()` 은 자격 행 하나마다 `S_SUCCESS` 를 돌려주므로 배치 초과 읽기가 없다.
  PR#7991 이 힙 경로를 대상에서 뺀 것이 구조상 일관적이다. **단 CUBRID 실측으로 재확인하지 않음 — 코드 판독.**
- **[src-query §2] key limit 은 outer 행마다 재무장된다** (.51, PR#7991 head, 2026-09-22):
  `scan_reset_scan_block()` → `scan_init_index_key_limit()` (`scan_manager.c:4944`). 그래서 상수 1 로 충분하고,
  조인 결과가 1행으로 잘리지 않는다. `key_limit_reset` 플래그는 **다른 축**이다 — 한 스캔 안에서 range 마다
  다시 줄지 여부(`scan_manager.c:2934` 등).
- **[src-query §3] 해시 semi/anti 의 프로브 조기 종료 여부 — 미확인** (.51, 2026-09-22): **미수정·미조사.**
  PR#7991 은 해시 플랜을 대상에서 제외했는데, 참조 구현은 해시 프로브에서 첫 매치 후 버킷 체인 탐색을 멈춘다.
  CUBRID 의 hash list scan 은 `S_LIST_SCAN` 이라 같은 `scan_next_scan_local` 게이트 경로를 지나는 것으로 보이나
  **마킹이 붙는지 확인하지 않았다.** 붙지 않으면 같은 키에 inner 가 많을 때 체인을 끝까지 훑는다.
- **[src-optimizer §3] NL semi/anti 의 조기 종료가 비용 모델에 반영되는지 — 미확인** (.51, 2026-09-22): **미조사.**
  참조 구현은 "첫 매치에서 멈춘다" 를 옵티마이저 비용에 할인으로 넣는다. CUBRID 가 inner 스캔 비용을 여전히
  전 매치 스캔으로 매기면 key limit 이 붙어도 그 플랜이 선택되지 않아 효과가 재현 질의 밖으로 나가지 않는다.
