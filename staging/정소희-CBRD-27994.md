## 확인한 사실 (develop)
- **공유 적중은 한 짝을 만든다**: `expr_compile_node_arith ()`(expr_compile.c:5325-5339)가 필터 등록부에서 같은 식을 찾으면 `expr_new_cell (…, EXPR_CSRC_SHARE, …)` 로 필터 결과 슬롯에 이은 칸 1개를 만들고 `cell_shared[cell] = true`·`bctx->n_shared++` 를 한다. `EXPR_CSRC_SHARE` 칸을 만드는 자리는 여기 하나다(grep). `expr_prog_finish ()` 가 `prog->n_shared = bctx->n_shared` 로 옮긴다(:6495).
- **되감기는 이 짝을 모른다** (`expr_build_mark ()`·`expr_build_rewind ()`, :2042-2083): steps·cells·cse·slots·guards·node_cells·cur_guard·in_branch 만 기록·복원한다. `n_cells` 가 줄어드는 자리는 되감기 하나이고, 호출자는 루트 거절(`expr_prog_compile_roots_impl ()` :6679)·하위 트리(`expr_compile_node ()` :4751)·필터 쪽(`expr_scan_side_compile ()` :2830 — 공유 칸이 생기지 않음) 셋.
- 그래서 공유 적중 뒤 그 식이 거절되면 `n_shared` 가 남고(칸 수보다 클 수 있다), 같은 칸 번호로 다시 만든 칸이 낡은 `cell_shared` 표시를 물려받는다(`only_compute_roots` 가 fetch·VALUE 만 하는 루트를 계산으로 본다, :6660).
- **이미지 리더가 그 어긋남을 거절한다**: `expr_image_get_prog ()` 는 `n_shared` 를 `[0, n_cells]` 로 읽는다(:8665). 투영 목록 이미지(`expr_valptr_prog_image_at_generation ()`)와 집계 피연산자 이미지(`expr_agg_prog_image_at_generation ()`)가 같은 빌드 코드를 쓰므로 둘 다 해당 — debug 는 서버 대조 assert(`expr_valptr_prog_settle ()` :9156, `expr_agg_prog_settle ()`), release 는 그 목록을 해석 실행으로 둔다(결과는 같다).
- 재현(빈 표에서도, debug SA·CS): `CREATE TABLE t (c0 DOUBLE, c1 INT, c2 BIGINT); SELECT c1, COUNT(LEAST(CAST(c1 AS DOUBLE), CASE c1 WHEN c2 THEN c0 ELSE c0 END)), MIN(CAST(c1 AS DOUBLE)) FROM t WHERE CAST(c1 AS DOUBLE) > 0 GROUP BY c1;` — LEAST 루트가 열끼리 단순 CASE 로 거절되며 공유 칸을 되감고, MIN 의 CAST 가 같은 번호로 다시 공유해 `n_shared` 2·칸 1.
- 반대 꼴: 거절된 루트 바로 뒤에 열만 오는 목록(`SELECT LEAST(…), c1 … WHERE CAST(c1 AS DOUBLE) > 0`)은 낡은 표시로 열 하나만 읽는 프로그램이 켜진다 — `;plan detail` 트레이스 `output list: active, columns covered 1/2 … steps: 0 … cells: 1 … shared from data filter: 1`(공유 칸 0), 이미지는 받아들여진다(1 ≤ 1). develop `36c7433d8` debug 동적.
- 식 컴파일 절은 csql `;plan detail` 세션의 CS 트레이스에만 찍힌다(`qdump_print_expr_compile_text ()` — `trace_plan_detail`), SA 의 SHOW TRACE 는 NULL.
