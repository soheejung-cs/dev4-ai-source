# CBRD-27798 — NUMERIC 키의 해시 정규화와 음수 scale 의 precision

작성: 정소희 (.51) · 기준 develop `569f3cad6`(측정은 `38c931e7d`) · 2026-11-12. 대상 모듈 노트: `modules/src-query.md` §3, `modules/src-base.md`(memory_hash) §3. 출처: claude-workspace `projects/CBRD-27798/세션기록-20261112.md`, PR#8414.

- **[src-query §3] 부동 NUMERIC 의 해시 정규화는 음수 scale 에서 값의 precision 을 자릿수로 믿는다** (.51, 38c931e7d·569f3cad6, 2026-11-12, SA 실측): `mht_get_hash_number ()`(memory_hash.c)는 부동 NUMERIC 을 `float_numeric_normalize_for_hash ()`(numeric_opfunc.c)로 정규화하는데, scale < 0 이면 `10^min(-scale, 40 - precision)` 을 곱하고 precision 40·scale < 0 이면 정규화를 건너뛴다. 고정 NUMERIC(예: `NUMERIC(38,-5)`)의 precision 은 열의 것(38)이고, 고정→부동 변환(numeric_opfunc.c 의 NUMERIC 변환기)은 `DB_HJOIN_NUMERIC_PRECISION_DEFERRED` 표시가 없으면 그 precision 을 그대로 header 에 옮긴다. 그래서 `NUMERIC(38,-5)` 의 1500000(계수 15, scale −5)이 1500 으로 정규화돼 같은 값의 NUMERIC(20,0) 1500000 과 해시가 갈린다. develop 해시 조인: `CAST (n38m5 AS NUMERIC)` 부동 키 대 NUMERIC(20,0) 5행 중 1행(USE_NL 5행). 해시 조인이 변환하는 키는 DEFERRED 로 `numeric_get_precision_digits ()` 를 세서 맞다. **PR#8414 에서 수정 중**(해시 리스트 스캔 부동 키·해시 조인의 변환 없는 부동 키가 해시 전에 자릿수를 셈 — 공용 정규화는 그대로).
- **[src-query §3] `mht_get_hash_number ()` 는 HASH 파티션의 행 배치 해시다** (partition.c `mht_get_hash_number (hash_size, key)`): 이 함수(와 그 정규화)의 출력을 바꾸면 기존 HASH 파티션 테이블의 행이 다른 파티션을 가리키게 된다 — 해시 결함은 이 함수 밖(쓰는 자리)에서 고친다.
- **[src-query §2] 해시 리스트 스캔의 키 쌍 도메인** (xasl_generation.c `pt_hash_key_domain ()`, PR#8414 판): 공통 도메인은 해시 조인과 같은 `domain_resolve_hash_key ()` 결과, 공통이 부동인 NUMERIC×NUMERIC 쌍은 변환 없이 정규화 해시(`qdata_hash_scan_key_float_numeric ()` — 고정 값은 `FIXED_TO_FLOAT_NUMERIC` 사본, 음수 scale 은 자릿수를 셈). 부동 키가 있는지는 스캔 open 때 regu 도메인으로 한 번(`HASH_LIST_SCAN.float_numeric_key`). CONNECT BY PRIOR 키는 도메인이 부동이지만 값은 피연산자 표현(고정)을 가진다.
