# staging — 정소희 · CBRD-27254 (히스토그램 선택도 null 비율 계약)

작성: 정소희(.52) · 기준 리비전 develop `c0e06bef9` (실측 설치본 `07480dfd1`, 두 리비전 간 선택도 코드 무변경) · 2026-09-22

- **[src-optimizer §2] 헬퍼의 non-null 조건부 계약은 조인 경로만이 아니라 모든 술어 노드에서 한 곳이 이행한다** (.52, `c0e06bef9`, 2026-09-22):
  `qo_expr_selectivity ()` 가 or_next 체인의 **노드마다** `pt_get_end_path_node (arg1|arg2)` 가 PT_NAME 이고 `null_frequency >= 0` 이면
  `(1 - null_frequency)` 를 곱한다(`query_planner.c:10606-10650`; CBRD-26202 #7180 도입, 27039 #7442 · 27059 #7473 · 26746 #7508 정련).
  comp·range·between·like·in·NE·NOT_* 가 전부 개별 소비 함수가 아니라 이 공통 후처리를 지나므로, `qo_comp_selectivity ()` 등만 보면
  "곱하는 호출자가 없다"로 오판한다(CBRD-27254 가 그 오판이었고 develop 에서 재현되지 않아 종결). 기존 항목 "조인 선택도 호출부의 (1-null_frequency)
  이중 곱 규약"의 일반화. **미수정 아님 — 결함 아님.**
- **[src-optimizer §2] 부정 술어의 NULL 차감은 곱 순서로 이미 맞다** (.52, `c0e06bef9`, 2026-09-22):
  헬퍼 조건부 sel_c → `qo_not_selectivity ()` 의 `1 - sel_c` → 공통 후처리 `× (1 - nf)` = `(1 - nf) - sel_abs`. 실측(30% NULL, 10,000행):
  `a NOT BETWEEN 200 AND 400` 참 0.559 / 추정 0.559, `a <> 500` 0.699/0.699, `s NOT LIKE 'v1%'` 0.56/0.56, `a NOT IN (1,2,3)` 0.700/0.697.
  `IS [NOT] NULL` 은 `not_null_calculated` 로 공통 곱에서 제외. 재현물 `claude-workspace/projects/CBRD-27254/repro/nullfrac_contract.sql`.
- **[src-optimizer §2] `null_frequency` 는 히스토그램과 같은 자리에서 함께 주석된다** (.52, `c0e06bef9`, 2026-09-22):
  `qo_get_attr_info ()` 가 세그먼트 노드에 `histogram = NULL, null_frequency = 0.0` 을 놓고 hist_stats 가 있으면 둘을 같이 채운다
  (`query_graph.c:5460-5473`), `set_seg_node ()` 가 술어의 PT_NAME 으로 둘을 함께 복사한다(`:3004`). 그래서 "헬퍼는 나눴는데 호출자는 곱하지
  않는" 조합(히스토그램 있음 ∧ nf 미지)이 구조적으로 생기지 않는다. 히스토그램 없는 컬럼은 nf 0.0 → 곱이 항등.
