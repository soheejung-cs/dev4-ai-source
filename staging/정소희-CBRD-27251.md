# 정소희 — CBRD-27251 (히스토그램 CHAR/VARCHAR 후행공백 규약) 환류 대기

작성: 정소희 (.50) · 기준 리비전 upstream/develop `6497720ec` (수정 PR#7977 `a82e6d6ae`) · 2026-09-17

- **[src-optimizer §2] 히스토그램 문자열 키 정규화는 `hist::string_key_size_for_column (column_type, s, size)` 하나가 정의한다 — 컬럼 타입이 CHAR 면 후행공백 제외, VARCHAR·BIT 는 바이트 그대로** (.50, PR#7977 a82e6d6ae, 2026-09-17): `histogram_reader.hpp` inline. 샘플러 `extract<std::string>`·`ndv_hll_hash`(histogram_sampler_sr.cpp)와 프로브 `histogram_extract_key`(histogram_cl.cpp, 인자 `column_type = reader.value_type ()`)가 공유. 그 전(develop 6497720ec)에는 프로브가 **리터럴 타입**을 기준으로 스트립해 VARCHAR 컬럼 + `'abcd '` 가 `'abcd'` MCV 에 맞았다(1,600행 재현 sel 0.125 vs 참값 100행). PR#7977 에서 수정.
- **[src-optimizer §2] 런타임 문자열 등가는 `db_string_compare`(string_opfunc.c) 가 `ignore_trailing_space=no`(기본, 히든 파라미터) 일 때 양쪽이 모두 패딩 타입(CHAR)일 때만 후행공백을 무시하고, `yes` 면 항상 무시한다(`ti = QSTR_IS_PADDED_LENGTH(t1) && QSTR_IS_PADDED_LENGTH(t2)`)** (.50, 6497720ec, 2026-09-17): 히스토그램 MCV 스윕(`string_values_equal_under_collation`)은 VARCHAR 로 DB_VALUE 를 만들어 이 함수를 부르므로 파라미터를 자동으로 따른다(`yes` 에서 `t_vc.c='abcd'` 0.2125=340행 ✓). `static bool ignore_trailing_space` 로 프로세스당 1회 캐시.
- **[src-parser §2] 타입체커는 `col <op> 'lit'` 에서 CHAR↔VARCHAR 를 `PT_ARE_COMPARABLE_CHAR_TYPE` 로 보고 리터럴을 컬럼 타입으로 강제변환하지 않는다** (.50, 6497720ec, type_checking.c:5511, 2026-09-17): 그래서 옵티마이저가 받는 상수 DB_VALUE 의 타입은 리터럴 타입(CHAR)이지 컬럼 타입이 아니다. 호스트변수는 :9601 에서 컬럼 타입으로 coerce 된다. 명시 `CAST(...)` 는 `PT_EXPR_INFO_CAST_SHOULD_FOLD` 없이는 접히지 않아 `qo_classify` 가 `PC_OTHER` → 히스토그램 경로를 안 탄다(1/NDV 폴백).
- **[src-optimizer §2] CHAR 컬럼 LIKE/REGEXP 의 히스토그램 추정은 저장값을 컬럼 정밀도(문자 수, `intl_char_count`)까지 재패딩해 매칭한다 — `histogram_repad_char_value`** (.50, PR#7977, 2026-09-17): 런타임은 패딩된 힙 값에 패턴을 적용하므로(`t_ch.c LIKE 'abcd %'` 340행) 스트립 저장값으로는 0.000625 로 과소추정했다. 정밀도·코드셋은 컬럼 노드 `data_type.precision/units`, 없으면 재패딩 없음. `intl_char_count` 가 다루는 코드셋 4종(ISO88591·RAW_BYTES·KSC5601_EUC·UTF8) 외는 건너뜀.
- **[src-optimizer §2] LIKE 항은 `LIKE 'abc'` → 등가, `LIKE 'abc%'`·`'abc %'` → 범위 항 + 잔여 LIKE 항으로 재작성되고, 잔여 LIKE 항의 sel 은 like추정/범위추정(상한 1)** (.50, 6497720ec 실측, 2026-09-17): `set optimization level 513` 출력의 term 은 sel 순 정렬이라 `term[0]` 만 보면 LIKE 추정을 오독한다 — REGEXP 항(재작성 없음)으로 확인하는 게 정확.
- **[src-optimizer §3] `ignore_trailing_space=yes` 에서 문자열 범위 추정(`string_domain_frac_lt`, 바이트 순서)은 파라미터를 무시한다** (.50, PR#7977 후에도, 2026-09-17): `t_vc.c < 'abcd '` 추정 200행 vs 참값 0. 히든 파라미터·기본 no 라 영향 작음. **미수정**(별건 후보).
