# staging — CBRD-28120 코드 사실

작성: 정소희 (.51) · 기준 develop `2e67e1d94` · 2026-11-18

- **[src-query §2] trace 의 EXPR_COMPILE 구간과 스캔 줄의 batch 표시는 세션이 플랜을 자세히 요청할 때만 찍힌다** (.51, `2e67e1d94`, 2026-11-18): `qdump_print_expr_compile_text ()`(query_dump.c:4271)가 `thread_get_thread_entry_info ()->trace_plan_detail`(csql `;plan detail`)을 보고, 없으면 필터가 컴파일돼 돌아도 아무 줄도 쓰지 않는다. 새 DB 2,000행 표에 같은 `SET TRACE ON` 을 `;plan detail` 없이·있이 돌려 확인(없으면 `SCAN` 줄에 batch 표시도 없음). 컴파일 여부를 trace 로 판정하는 TC·재현은 `;plan detail` 을 먼저 켠다.
- **[src-query §2] 스캔 필터 비교의 피연산자는 각자 guard 에서 컴파일되어 실패 가능 step 은 prologue 로 끌어올려지지 않는다** (.51, `2e67e1d94`, 2026-11-18): `expr_scan_side_compile ()` 이 쪽마다 `expr_rhs_begin (…, EXPR_GUARD_SCAN_SIDE, …)` 을 열고(그 쪽의 step 은 eval_pred () 가 그 쪽을 읽을 때만 도는 범위), `expr_step_hoist ()` 는 `cur_guard != 0` 에서 실패 가능 step 을 끌어올리지 않는다. 그래서 `col LIKE ?` 의 범위 경계(generic step)는 실행당 상수인데도 행마다 돈다 — 끌어올리면 앞 항이 거짓이라 인터프리터가 그 쪽을 안 읽는 실행에서도 첫 행에 계산해 오류를 새로 낼 수 있다. **미수정**(수정 예정 CBRD-28120: step 을 제자리에 두고 실행당 한 번 계산).
- **[src-query §3] 상관 부질의를 다시 돌릴 때 출력 목록 regu 의 값이 지워진다 — 실행당 prologue 는 다시 돌지 않는다** (.51, `2e67e1d94`, 2026-11-18, 정적): `qexec_start_mainblock_iterations ()`(query_executor.c:21162)가 `qexec_clear_regu_list (…, outptr_list->valptrp, true, false)` → `qexec_clear_arith_list ()` 의 `pr_clear_value (list->value)`. 컴파일된 프로그램은 같은 실행(query_id)에서 prologue 를 다시 돌리지 않으므로(`expr_prog_prepare ()`), 실행당 한 번 계산한 값을 노드 값(`arithptr->value`) 주소로 두면 둘째 바깥 행부터 빈 값이다 — 프로그램 소유 슬롯에 복제해야 한다.
- **[src-query §2] 필터의 공유 목록에 페이지 배치가 싣지 못하는 타입의 슬롯이 오르면 배치를 포기한다** (.51, `2e67e1d94`, 2026-11-18, 동적): `expr_scan_pred_share_build ()` 는 슬롯을 가진 step 의 셀을 공유하고, 배치는 공유 값의 타입을 못 실으면 `a shared value of a type the batch does not carry`(expr_batch.c:2312·5101)로 거절한다. VARCHAR 결과 슬롯 하나가 40만 행 스캔을 `batch pages` 에서 행 경로로 돌렸다(CBRD-28120 구현 중 실측).
- **[src-query §2] T_CONCAT 의 generic 피연산자 규칙은 oracle_style_empty_string 이 꺼져 있으면 `L?r` 이다** (.51, `2e67e1d94`, 2026-11-18): `expr_generic_operand_spec ()` — 왼쪽이 NULL 이면 오른쪽을 읽지 않으므로 확인 step(`EXPR_KID_jump_skip_generic`, `alias_of` 로 generic step 을 가리키고 out_cell 이 같은 셀)이 앞에 붙는다. 셀의 생산 step 을 out_cell 로 찾을 때 이 확인 step 을 건너뛰어야 한다.
- **[src-query §2] 페이지 배치의 프로그램 번역에서 generic step 은 `EXPR_STEP_OTHER`(행 경로)다** (.51, `2e67e1d94`, 2026-11-18, 정적): `expr_prog_step_info ()` 의 분류. 데이터 필터의 배치는 행마다 kernel 을 부른다(perf: `expr_batch_run → expr_scan_pred_eval_kid → expr_run_range → expr_k_generic`).
