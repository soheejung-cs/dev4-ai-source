# 정소희-CBRD-27962 — 파생 테이블 열 형은 접기 전에 정해지고 접기가 항목 형을 바꿈 (src/parser)

작성: 정소희 (.51) · 기준 develop `953e83256` · 2026-11-06. 출처: `/harness-implement` 배치(`claude-workspace/projects/CBRD-27932/구현배치-20261106.md`, 건별 `projects/CBRD-n/`). 동적 확인은 `MALLOC_CHECK_=3 MALLOC_PERTURB_=165`. 대상 모듈 노트: `modules/src-parser.md` §2·§3.

## 확인한 사실 (develop)
- **[src-parser §2] 이름 해석은 파생 테이블을 접기 없이 형 검사하고 그 형으로 열을 정한다**: `pt_bind_names ()`(name_resolution.c:1358-1361)가 `sc_info->donot_fold = true` 로 `pt_semantic_type ()` → `pt_bind_spec_attrs ()` 가 as_attr_list 형을 선택 목록 형으로. 바깥 질의의 이름은 이 형에 묶인다. 뒤 의미 검사(접기 켬)가 항목 형을 바꿔도 맞추지 않는다. CTE 는 `pt_bind_names_in_cte ()` 가 접은 뒤 형으로, 뷰는 `mq_set_types ()`(view_transform.c:8739)가 열 형으로 CAST 해 어긋나지 않는다.
- **[src-parser §3] `COALESCE (정수, NULL)` 은 VARCHAR, `COALESCE (NULL, 정수)` 는 INTEGER**: 오버로드 `(number, ANY) → VARCHAR` 에서 ANY 가 NULL 과도 '같은 형'(`pt_are_equivalent_types ()` func_type.cpp:1344)이라 `(number, number)` 보다 많이 맞는다. NVL·IFNULL 도 같다.
  - 실측(JDBC): develop 의 파생 열이 825373492(문자열 '1234' 바이트), `a + 1` 1100836660, UNION ALL 파생은 형 통합이 DOUBLE 이 되어 1072693248·8.
  - **수정됨 — PR#8435 `73ae5c347`·`cfdef8ea8`(미머지)**: 바깥 SELECT 형 검사 끝에서 형 열거값이 바뀐 파생 열 항목에 열 형 CAST(항목과 열은 숨은 항목 포함 위치로 짝 — 아래). 오버로드 규칙은 그대로(바꾸면 비파생 SELECT·CTAS 형까지 바뀜).
- **[src-parser §2] 파생 테이블 열은 부질의 선택 목록에 위치로 묶인다 — 숨은 항목 포함**: XASL 은 `spec.as_attr_list` 의 i 번째를 부질의 리스트 파일의 i 번째 열(숨은 열 포함)로 읽는다(`pt_to_position_regu_variable_list ()` xasl_generation.c:16075 계열). 사용자가 쓴 파생 테이블은 이름 해석(`pt_get_attr_list_of_derived_table ()` name_resolution.c:11702)이 숨은 항목이 붙기 전에 열을 만들고, ORDER BY 숨은 항목은 모두 끝에 덧붙으므로(semantic_check.c:15520, view_transform.c:2714·16626) 마지막 열 뒤로 빠진다. 반면 세션 변수 대입 + 선택 목록 밖 열의 ORDER BY 를 바꾸는 `mq_rewrite_order_dependent_query ()`(view_transform.c:15943)의 `dt_sort` 는 순서 무관 항목(숨은 정렬 항목 포함)마다 as_attr 를 만들고 뒤에 `sx` 항목을 덧붙여, **숨은 항목이 앞에 오고 그 항목에도 열이 있다**. 선택 목록과 as_attr_list 를 짝짓는 코드가 숨은 항목을 건너뛰면 이 꼴에서 짝이 밀린다(PR#8435 첫 커밋 — 첫 CI 의 `bug_bts_17424`·`cbrd_27510/03_session_variable_types` 가 `-181`, NUMERIC 은 조용히 반올림; `cfdef8ea8` 에서 고침).
