# CBRD-28049 — page batch fallback 의 남은 오류, 필터 이미지의 공유 목록 줄 수

작성: 정소희 (.51) · 기준 develop `a7f220d5d` · 2026-11-12. 대상 모듈 노트: `modules/src-query.md` §2 「스캔 필터 확장」·§3, `modules/src-storage.md` §2. 출처: claude-workspace `projects/CBRD-28049/세션기록-20261112.md`, PR#8515(draft, 미머지).

- **[src-query §3] page batch 가 청크를 행 경로로 넘길 때(EXPR_BATCH_FALLBACK) 청크가 세운 오류를 지우지 않았다** (.51, a7f220d5d debug·release, gdb·SA·CS 실측): 넘기기 전에 오류를 세우는 자리는 셋 — `eb_filter ()` 의 행 오류(행마다 평가하는 항의 `V_ERROR`, expr_batch.c:4963), IN 리프·문자열 리프의 압축 해제 실패(:1878·:1988, `lz4_decompress ()` 가 ER_GENERIC_ERROR). 나머지 fallback 자리(약 45곳)는 오류를 세우지 않는다. FALLBACK 을 받는 곳은 `scan_batch_iter_next ()`(scan_manager.c)와 qexec 의 `expr_chunk_push ()` 루프 둘이고, 둘 다 청크의 첫 슬롯부터 행 경로로 다시 걷는다. 행 경로가 LIMIT·EXISTS 로 그 행 전에 멈추면 질의는 성공하고 오류가 남는다. **PR#8515 에서 수정 중** — `expr_batch_run ()` 한 곳에서 청크 전 오류 등급 오류가 없었으면 지우고 ER_INTERRUPTED 는 올린다(`er_errid_if_has_error ()` 로 앞뒤를 잰다 — NUMERIC 산술이 -427 을 경고로 세운다).
- **[src-storage §2] `cubstorage::bestspace::find ()` 는 들어올 때 오류 등급 오류가 있으면 그 오류로 바로 돌아간다** (bestspace.cpp:1533 "early return or clear stale error", a7f220d5d gdb): `heap_find_bestpage ()` ← `heap_get_insert_location_with_lock ()` ← `heap_insert_logical ()` 경로라, 같은 요청에서 앞서 남은 오류가 있으면 힙에 행을 넣는 문장이 그 오류로 실패한다. CBRD-28049 의 release 증상: `INSERT … SELECT … WHERE EXISTS (…)` 가 -427 로 실패(SA·CS), `CREATE TABLE … AS SELECT` 는 SA 에서만 실패(CS 는 성공 — 요청이 나뉘는 것으로 보임, 미확인). UPDATE(같은 꼴)는 성공했다. 남은 오류가 결과로 드러나는 자리로 기억할 것.
- **[src-query §2 「스캔 필터 확장」] 필터의 공유 목록(`EXPR_PRED.share[]`)은 공유 가능한 노드마다 한 줄이라 줄 수가 칸 수를 넘을 수 있다** (.51, a7f220d5d debug SA gdb): `expr_scan_pred_share_build ()` 는 `node_cells[]` 의 shareable·슬롯 소유 노드를 모두 등록한다. CSE 가 같은 식의 두 노드에 한 칸을 주면(`CASE x WHEN x` 의 x, `expr_cse_find ()`; 교환 짝 `a+b`/`b+a` 도 `expr_cse_find_commuted ()`) 두 줄이 같은 칸·슬롯을 가리킨다 — 예: x = `CAST(CAST(t0.c0 AS BIGINT) AS DOUBLE)` 이면 node_cells 5(칸 1,2,1,2,3), 프로그램 칸 4. 이미지 리더 `expr_scan_pred_image_unpack ()` 는 줄 수를 `[0, n_cells]` 로 읽어 이 이미지를 거절했다(debug: `expr_scan_pred_settle ()` assert expr_compile.c:9125, release: 필터 해석 실행). 재현 꼴은 바깥 VARCHAR 열의 그 CASE 를 LEFT OUTER JOIN 의 ON 절에 둔 것(안쪽 스캔의 필터, 바깥 열은 값) — WHERE 에 두면 필터가 컴파일되지 않고, INT 열이면 CASE 노드가 슬롯이 없어 줄 4 ≤ 칸 4 로 통과, 상관 부질의 꼴도 통과. **PR#8515 에서 수정 중** — 리더 상한을 `EXPR_MAX_STEPS`(쓰는 쪽 node_cells 의 크기)로, 줄마다 칸 범위 검사는 그대로. CBRD-27994 §3 항목의 "스캔 필터 쪽 짝 assert … 원인이 다르다 — 미확인" 의 원인이 이것이다.
