## 확인한 사실 (develop)
- **[src-optimizer §3] 외부 조인 뒤 명시적 INNER JOIN 의 ON 에 널 공급 쪽을 섞은 OR-of-AND 가 분배되면 오답** (.52, 99fa309ca, 2026-11-06):
  - `o left join i on … inner join j on (i.x is null and j.y = 1) or (i.x = 2 and j.y = 2)`(분배 후 4절)에서 i 의 파생 제약이 외부 조인 아래 i 스캔으로 내려가, i 행(x=5)을 걸러 NULL 확장행을 만들고 ON 이 참이 된다 — 정답 0행, develop 1행 `(1, NULL, 1)`.
  - 분배 후 절이 100 을 넘으면(COMPACT 경로) develop 은 추출하지 않아 0행이다. PR#8375 는 이 꼴도 추출해 1행이 된다(PR 회귀, 리뷰 g12-04).
  - **미수정**(develop) — `repro/g12-04_07` 1번.
- **[src-query §3] `eval_pred ()` 는 오른쪽 선형 PRED_EXPR 트리를 전제한다** (.52, 정적 + 동적, 2026-11-06):
  - rhs 를 따라 반복하고 lhs 로는 재귀한다(query_evaluator.c:2050 부근). 왼쪽으로 깊은 OR 가 중첩 한도 400 을 넘으면 "maximum allowed nesting level(400)" 로 질의가 거절된다.
  - PR#8375 head 는 `(x = 1 and y = 1) or a = 1 or … or a = 450` 을 왼쪽 깊은 PT_OR 로 남겨 거절된다(develop 2). AND 분기를 맨 뒤로 옮기면 둘 다 2.
  - 판정 단계의 정적 분석: develop 의 100절 초과(COMPACT) 경로도 AND 묶음 분기가 400 을 넘으면 같은 모양이 된다 — 실행으로 확인하지 않았다.
- **[src-parser §3] `pt_split_join_preds ()` 는 WHERE 목록이 완전한 CNF 라고 가정한다** (.52, PR head 동적):
  - parser_support.c:2918-2920 의 assert("It is either fully CNF or not at all"). `next` 를 가진 PT_OR 원소(통째로 둔 OR-of-AND 뒤에 다른 conjunct)가 계층 질의 경로로 들어오면 debug 가 abort 한다.
  - develop 은 분배하므로 그런 원소가 없다. PR#8375 head 에서 `where ((a = 1 and b = 1) or (a = 2 and b = 2)) and c > 0 start with … connect by …` 가 abort(release 미확인) — `repro/g3_g4/noparam` 5번.
- **[src-parser §3] (+) 표기의 ON 이동은 술어의 최상위 표시만 본다** (.52, PR head 동적):
  - OR-of-AND 안의 `i.y(+) = 10` 이 통째 PT_OR 아래에 있으면 ON 으로 옮겨지지 않고 WHERE 에 남아 NULL 확장행이 빠진다. develop 은 분배된 절마다 표시가 있어 2행, PR head 1행 — `repro/g4` 2번.
- **[src-query §3] UPDATE·DELETE·MERGE 안의 부질의는 재작성이 두 번 돈다** (.52, 정적 + PR head 동적):
  - 1차 mq_translate, 2차 XASL 생성용 사본(xasl_generation.c:25273·24667). 원본 인자에서 파생 절을 뽑는 재작성은 두 벌을 만든다 — PR head 의 UPDATE 부질의 플랜에 열 범위 파생 절이 두 벌, 하나의 sel 250.375(1 초과).
  - 2차 재작성의 `qo_apply_range_intersection ()`(query_rewrite_term.c:4424·4482·4485)에서 파생 노드가 같은 열의 사용자 범위를 흡수하면, 인덱스가 그 항을 안 쓸 때 `make_pred_from_plan ()`(plan_generation.c:1990)이 파생 절과 함께 사용자 조건을 버린다 — PR head 에서 DELETE 가 남길 행을 지웠다(자동 파라미터화 끔 문맥에서만).
- **[src-optimizer §2] 자동 파라미터화가 꺼지는 조건** (.52, 정적, query_rewrite.c:504-506):
  - `hostvar_late_binding=yes`, `max_plan_cache_entries` ≤ 0, `cannot_prepare`, PL/CSQL 정적 SQL(`is_parsing_static_sql`), `is_skip_auto_parameterize`. conf 키는 `max_plan_cache_entries`(매크로 `PRM_ID_XASL_CACHE_MAX_ENTRIES` — 이름이 다르다).
  - 이 문맥에서는 상수가 호스트 변수로 바뀌지 않아 범위 병합·교집합이 상수로 일어난다 — 재작성기 변경은 이 판으로도 돌려야 한다(자가진화 #095).
- **[src-parser §3] 한 열 OR-of-AND 는 비결정 함수가 있어도 분배된다** (.52, 정적, develop 동일 — 리뷰 G4-06):
  - DRAND·NEXT_VALUE·세션 변수·메서드 호출이 든 인자도 분배되어 복제 평가된다. 동적으로 확인하지 않았다. **미수정**.
