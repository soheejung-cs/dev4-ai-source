# 정소희 — CBRD-28031 (PR#8490 리뷰에서 확인한 코드 사실)

작성: 정소희 (.51) · 기준 리비전 develop `4255a337d`(PR#8490 merge-base) · 2026-11-13

- **[src-storage §2 / src-query §3] 사용자 취소는 확인하는 쪽이 지우는 한 번짜리 신호다 — 그 뒤의 `er_clear ()` 는 취소를 영구히 잃는다** (.51, 4255a337d, 2026-11-13): `pgbuf_fix` 경로(page_buffer.c:2354-2356)와 `db_sleep ()`(arithmetic.c:5121-5125)은 `logtb_is_interrupted (thread_p, true, …)` 로 확인하면서 `logtb_is_interrupted_tdes ()` 가 `tdes->interrupt = false`(log_tran_table.c:3094)로 플래그를 끄고 `ER_INTERRUPTED` 를 세운다. 그래서 그 오류를 `er_clear ()` 로 지우고 같은 자리를 다시 평가해도 취소는 다시 나오지 않는다(0 나누기 같은 결정적 오류와 다름). 미리 평가·재시도·투기 실행이 오류를 지우는 코드는 `ER_INTERRUPTED` 를 갈라야 한다. PR#8490 의 병렬 인덱스 스캔 워커 미리 평가가 이 꼴로 취소를 잃는다 — 단위 suite dev4 `unit/query/px_scan_index_leaf_slot_walker.ahead_interrupt`(head 35a151f37: 확인점 66 중 45 유실, base 0). **미수정**(PR 리뷰 지적 게시 11-13, 작성자 대응 전). 규칙 dev4 자가진화 #123.
