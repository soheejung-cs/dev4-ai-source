## develop 공통 (SERVER)
- **[src-query §2] 힙 스캔의 기본은 PEEK 이고 술어 평가 뒤 페이지 LSA 가 바뀌면 COPY 로 재시도한다** (.52, `a7a1db84b`, 2026-09-16): `scan_next_heap_scan` 이 `is_peeking = scan_id->fixed`(= `ACCESS_SPEC_TYPE.fixed_scan`, xasl.h:1104)로 `heap_next` 를 부르고, `eval_data_filter` 뒤 `PGBUF_IS_PAGE_CHANGED(page_watcher.pgptr, &ref_lsa)` 면 `is_peeking = COPY` 로 같은 OID 를 다시 읽는다(scan_manager.c:5905-5989). 실행기가 pgbuf LSA 를 직접 보는 자리 — 경계 누수. ✅ 스캔 매니저에 pgbuf/RECDES 타입을 더 노출하는 변경은 이 자리를 넓힌다.
- **[src-storage §2] `heap_attrinfo_read_dbvalues` 는 복사가 아니라 포인팅이다** (.52, `a7a1db84b`, 2026-09-16): `heap_attrvalue_read` 가 `heap_attrvalue_point_fixed/variable` 로 RECDES 안 위치를 잡고 `pr_type->data_readval(&buf, …, copy=false)` 를 부른다(heap_file.c:10948-10989, :11073). 문자열·NUMERIC DB_VALUE 는 레코드(=페이지 또는 페이지 사본)를 가리키고 `need_clear=false`. **값의 수명 = 레코드의 수명**. ✅ 스캔 셀을 행 밖으로 들고 나가는 코드(프로그램 셀 캐시, 리스트 지연 기록)는 여기서 깨진다.
- **[src-storage §2] 래치 없는 스캔 사본은 `copy_to_local_cache && is_queryscan` 일 때만 켜지고 OOM 이면 조용히 COPY 로 강등된다** (.52, `a7a1db84b`, 2026-09-16): `heap_scancache_start_internal` 이 `pgbuf_copy_buffer_alloc()` 성공 시 `read_mode = HEAP_SCAN_READ_LOCAL_CACHE`(heap_file.c:6504-6517), `heap_next` 계열이 `HEAP_SCAN_IS_LOCAL_CACHE_READ` 면 `pgbuf_copy_page_for_scan` 으로 16KB 복사(:7694, :8033). CBRD-27041 의 설계. 실패는 `er_log_debug` 만 — 성능 저하가 에러 없이 일어난다. ✅ 스캔 성능 편차를 볼 때 이 강등을 의심.
- **[src-query §2] 리스트 파일 값 읽기(`TYPE_POSITION`)도 peek 다** (.52, `a7a1db84b`, 2026-09-16): `fetch_peek_dbval` 이 `qfile_locate_tuple_value` 뒤 `data_readval(…, false /* Don't copy */)`(fetch.c:4726-4737). 행당 강제 복사는 XASL 블록 출력의 튜플 패킹(`qfile_generate_tuple_into_list`, 값당 8B 헤더 + 8B 튜플 길이, query_list.h:229-236) 한 번이다.
- **[src-query §2] 리스트 파일은 `QMGR_TEMP_FILE.membuf` 메모리 페이지를 먼저 쓰고 `membuf_npages` 를 넘으면 임시 볼륨 페이지로 간다** (.52, `a7a1db84b`, 2026-09-16): `qmgr_get_new_page`(query_manager.c:2870-2882), 크기 파라미터 `temp_file_memory_size_in_pages`(system_parameter.c:238). 중간 결과가 처음부터 파일 페이지 형식인 것이 database-reference(사설 청크 우선)와의 구조 차이.
- **[src-parser §2] `CAST(<date 컬럼> AS INT)` 는 실행이 아니라 시맨틱 검사에서 거부된다** (.52, `a7a1db84b`, 2026-09-16 실측): "Semantic: Cannot coerce [dba.hc].dt to type integer"(-494), prepare 자체가 실패. 런타임 변환 오류를 시험하려면 `CAST(<varchar 컬럼> AS INT)`(-181)를 쓴다. `1/0` 리터럴도 파서가 접으므로 `1/?` 에 0 바인드. ✅ "실행 시 오류 순서" TC 가 시맨틱 오류로 통과하는 것처럼 보이면 이 함정.

## PR#7658 한정 (feature/expression-compile)
- **[src-query §2 expr_compile] 실패 가능 스텝의 호이스팅 조건은 "메인 루프 + 앞에 실패 가능한 행 스텝 없음"** (.52, `9a13c297d`, 2026-09-16): 끌어올린 스텝은 첫 행의 모든 행 스텝보다 먼저 돌므로 `select cast(s as int), 1 / ?`(`'abc'`, 0)에서 두 오류 중 해석 경로가 먼저 내는 것(cast)을 유지하려면 뒤의 `1/?` 를 행 루프에 남겨야 한다. `expr_step_hoist` 가 빌드 순서상 앞 스텝을 `expr_step_is_fallible` 로 검사. A/B(develop `519cc1a43` SA 모드) 오류 순서 프로브 6건 byte 동일, TC `cbrd_27215_hoist_chain` h8~h13.
- **[src-query §2 expr_compile] 점프 경계는 `remap[]` 이 아니라 `remap_boundary[]`(그 위치 이후의 첫 행 스텝)로 되메운다** (.52, `2628b943d`, 2026-09-16): lazy 노드의 NULL 검사 점프가 프롤로그로 올라간 스텝(E 프롤로그의 호스트 변수 읽기)을 가리키면 행 루프가 뒤로 뛰어 무한 루프 — `a + (? + 1), (? - 1) * n` 은 **변경 전 head `68909640f` 에서도 재현**(기존 결함).
- **[src-query §2 expr_compile] 호스트 변수는 위치로 키가 잡힌다 — 값 공유 대상이 아니다** (.52, 2026-09-16 trace 실측): `sum(a*?), sum(a*?)` 는 셀 두 개. 리터럴 값 공유(`expr_literal_same`)는 NUMERIC 에서 `DB_VALUE_NUMERIC_IS_VALUE_NEGATIVE` 도 비교해야 한다 — 빠뜨리면 `n * 1.5` 와 `n * -1.5` 가 한 셀(전체 CTP 로 발견, TC `cbrd_27215_literal_sign`).
- **[src-query §2 expr_compile] 호스트 변수가 든 투영·필터는 D26 이전엔 컴파일되지 않았다** (.52, `2628b943d` 이전): `DB_TYPE_VARIABLE` 도메인이라 컴파일이 거부됐고, 지금은 한 행(`EXPR_DOMAIN_DEFER_ROWS`)을 해석 경로에 넘겨 도메인을 받은 뒤 컴파일, 재실행 시 프로그램 값에서 루트 도메인을 다시 정한다(`qdata_valptr_prog_resolve_domains`, `qexec_clear_regu_var` 가 `original_domain` 복원). ✅ "Cannot coerce value of domain integer to domain *variable*" 가 준비문 재실행에서 나오면 이 복원 누락.
