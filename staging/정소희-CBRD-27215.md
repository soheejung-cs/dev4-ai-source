`cub_alloc`/`cub_free(__FILE__, __LINE__)` 로 `#define` 치환한다. 그래서 소스에 raw `malloc` 을 써도
`cubrid memmon` 이 **파일:줄 단위**로 집계한다(통계 이름은 basename 이 아니라 마지막 `/src/` 이후 경로 —
`memory_monitor_sr.hpp` 의 `m_target_pos`). 조건: 그 파일이 `memory_wrapper.hpp` 를 **마지막에** include 해야 하고
CI(`.github/workflows/check.yml`)가 이를 강제한다.
**`posix_memalign` 은 치환 목록에 없다** — 정렬 할당은 `cub_aligned_alloc ()`(CBRD-26964, `memory_cwrapper.h:202`)를

### clear 루틴은 플래그에 따라 표시를 **반대로** 읽는다
`qexec_clear_regu_var ()` TYPE_CONSTANT(`query_executor.c:1551-1566`) 와 `qexec_clear_agg_list ()`:
- `XASL_DECACHE_CLONE` **있음** → `CLEAR_AT_CLONE_DECACHE` 표시가 **있는** 값만 `pr_clear_value`
- **없음** → 표시가 **없는** 값만

`use_xasl_clone=false` 로 푼 트리는 그 표시가 하나도 없다(`stream_to_xasl.c` 의 `4770`·`5716`·`5736`·`6024`·`6043`·`3633` 이
전부 `use_xasl_clone` 가드 아래). 따라서 **표시 없는 트리에 플래그를 세운 단일 패스는 값을 하나도 해제하지 않는다.**
원샷 경로가 2패스(무플래그 최종 clear → 플래그 pass)인 이유가 이것이다.

### px 워커는 자기 트리를 갖는다

### 산술 커널의 NULL 처리 순서
`EXPR_ARITH_PROLOGUE` 가 두 피연산자의 NULL 을 **타입 가드(`EXPR_ARITH_REQUIRE_TYPE`)보다 먼저** 걸러
`PRIM_SET_NULL (step->out)` 후 반환한다. 커널 선택만 타입으로 하고 실행은 NULL 을 이미 다룬다.
호스트 변수의 타입은 `expr_leaf_type ()` 이 바인딩된 값에서 얻으므로 NULL 바인딩은 `DB_TYPE_NULL` 이 되고
`expr_arith_kernel ()` 에 항목이 없어 거절된다(→ CBRD-27455).

### 해석 경로의 NULL 시맨틱·오류 순서 (csql 실측)
산술만 전파: `a*?`·`a+?`·`a/?` → NULL (`a / NULL` 은 0 나누기 오류가 아니다).
비전파: `nvl(?, a)`·`coalesce(?, a)`·`nullif(a, ?)` → a 값, `case when a > ?` → else 분기, `a > ?` → NULL.
오류 순서: `(a / (a-10)) * ?` (?=NULL) → **0 나누기 오류**(왼쪽 먼저 평가) / `? * (a / (a-10))` → **NULL**(왼쪽이 NULL 이라 오른쪽 미평가).
