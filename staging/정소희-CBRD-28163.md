# 정소희 — CBRD-28163 (페이지 래치 타임아웃 뒤 waiter_exists, 철회 중 래치 대기)

작성: 정소희 (.51) · 기준 리비전 develop `ef12ae8ce` · 2026-11-17 — PR#8490(CBRD-28031) 머지 뒤 G4-R2-01 재현에서

- **[src-storage §3] 래치 대기가 타임아웃 나도 BCB 의 `waiter_exists` 는 지워지지 않는다 — 그 뒤로는 READ 로만 잡힌 페이지의 READ 요청도 막힌다** (.51, ef12ae8ce, 2026-11-17): `pgbuf_latch_bcb_upon_fix ()` 는 READ 로 잡힌 페이지에 대한 READ 요청을 `waiter_exists` 가 서 있으면 막는다(page_buffer.c:7043). 대기가 타임아웃 나면 `pgbuf_timed_sleep ()` 이 `pgbuf_timed_sleep_error_handling ()`(:7859)으로 그 스레드를 대기열에서 빼고 남은 READ 대기자에게 래치를 줄 뿐, 대기열이 비어도 표시를 지우지 않는다(쥔 쪽이 래치를 놓을 때의 깨우기 처리에서야 지워진다). 재현: 100행 힙 페이지를 `sleep (1)` 스캔이 쥔 동안 같은 페이지의 UPDATE 가 30초 래치 타임아웃(-836·-72)하면, 뒤이은 `select count (*)` 가 30.9초 기다린 뒤 -836·-72 로 철회된다(UPDATE 없이는 0.1초). CBRD-26425(`58cef8e01`, 원자 래치) 전에는 `pgbuf_is_exist_blocked_reader_writer ()` 로 대기열을 직접 훑었다. CBRD-27084(`e8b961468`)는 flush 깨우기·인터럽트 경로만 맞췄다. CBRD-27739(같은 함수의 fcnt 누수)의 gdb 관찰 waiter=1·대기열 빔도 이 표시다. **미수정**(develop) — CBRD-28163 / PR#8587 draft(`cae32d077`, 미머지: 포기 경로의 세 출구에서 막힌 reader·writer 가 없으면 표시를 지움). 같은 표시의 다른 원천 — 조건부 래치 거절(:7092-7095·:7108-7112 가 CAS 로 세우고 :7227-7259 에서 줄 서지 않고 돌아감)은 PR 범위 밖으로 남겼다(사용자 결정 11-17). 맨 앞이 포기할 때 flush 대기자 뒤의 READ 대기자는 승계받지 못한다(case 3 루프가 flush 대기자에서 멈춤, develop 동일 — 독립 리뷰 indep-3). 재현 claude-workspace `projects/CBRD-28031/repro/W1-waiter-exists-timeout/`, 단위 dev4 `unit/storage/page_buffer.timed_sleep_error_handling`, 모델 dev4 `tla/storage/latch_waiter_flag`.
- **[src-storage §2] 철회 중인 트랜잭션의 래치 대기는 타임아웃이 없다** (.51, ef12ae8ce, 2026-11-17): `pgbuf_timed_sleep ()` 은 대기가 타임아웃 나도 `logtb_is_current_active () == false` 면 `try_again` 으로 다시 기다린다(page_buffer.c:8015). 그래서 철회 경로가 다른 스레드가 쥔 페이지를 다시 고정해야 하면, 그 스레드가 놓을 때까지 끝나지 않는다(아래 재현에서 90초 동안 두 번째 -836 이 없었다).
- **[src-transaction §2 / src-storage §3] 고유 인덱스에 쓰다가 철회되면, 철회가 고유 통계를 되돌리려고 그 B-tree 의 루트를 READ 로 고정한다** (.51, ef12ae8ce, 2026-11-17, gdb): `return_error_to_client → xtran_server_abort → log_abort → log_abort_local → log_update_global_btid_online_index_stats → … logtb_tran_update_stats_online_index_rb → btree_get_class_oid_of_unique_btid → btree_fix_root_with_info (READ)`. 같은 트랜잭션의 바깥 커버링 스캔이 그 루트(키가 적으면 리프와 같다)를 쥔 채 저장 함수를 부른 상황 — CBRD-27591 의 커버링 꼴, CBRD-28031 머지 이후 — 에서는 위 두 사실과 겹쳐 문장이 영구히 멈춘다(클라이언트가 끊겨 바깥 스레드가 -186 으로 빠질 때까지). 비고유 인덱스는 이 재고정이 없어 래치 타임아웃 뒤 오류로 끝난다. 재현 claude-workspace `projects/CBRD-28031/repro/G4-R2-01-develop-hang/`, CBRD-27591 코멘트 4778614.
