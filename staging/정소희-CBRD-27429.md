# 정소희 — CBRD-27140/27429 (PR#7856·#7957) 에서 확인한 소스 사실

작성: 정소희 (.50) · 기준 리비전: develop `519cc1a43` (27140 머지 직후) · 2026-09-11 ~ 09-17
상태: **환류 대기** — 모듈 §2·§3 로 옮기면 이 파일을 지운다.

- **[storage §2] `heap_get_num_objects()` 는 상태가 아니라 행 수를 반환한다** (.50, 2026-09-16 확인, 기준 `519cc1a43^`):
  `heap_file.c` 의 그 함수는 `*nobjs = heap_hdr->num_recs;` 뒤 **`return *nobjs;`** 로 끝난다. 그런데 통계 폴백
  호출부(`statistics_sr.c:356`)는 `if (heap_get_num_objects (…) == NO_ERROR)` 로 비교했다 — `NO_ERROR` 가 0 이므로
  이 조건은 "성공하면"이 아니라 **"행 수가 0 이면"** 이었고, 힙에 행이 있을 때만 대입이 건너뛰어져 `rs_total_rows`
  가 0 으로 남았다. 도입은 `f7432203a` [CBRD-26936] (#7286, 2026-07-15) 의 신규 폴백 경로.
  **수정됨** — CBRD-27140(`519cc1a43`)이 시그니처를 `int heap_get_num_objects (…, INT64 *nobjs, …)` + `NO_ERROR`/
  `ER_FAILED` 반환으로 바꿔 계약과 관용구를 맞췄다. TC `bug_bts_5048` 의 기대값 `0,0` 은 이 버그가 만든 값이었고
  `1,6`(커밋 행수)으로 고쳤다.
- **[storage §2] 통계 폴백은 NDV 가 없을 때만 탄다** (.50, `519cc1a43`): `stats_update_statistics_internal` 은
  `use_provided_ndv` 이고 `class_attr_ndv->total_rows > 0` 이면 그 값을 쓰고, **0 일 때만** heap 메타데이터로 떨어진다.
  정상 경로(히스토그램 풀스캔)는 행 수를 같이 실어 보내므로 이 분기에 들어오지 않는다 — 위 결함이 오래 안 드러난 이유이고,
  트랜잭션 안에서 `UPDATE STATISTICS` 를 부르는 케이스처럼 폴백을 타야 노출된다. **미수정**(현재 계약)
- **[storage §2] 통계 재수집은 기존 표현을 먼저 읽고 다시 쓴다** (.50, `519cc1a43`): `statistics_sr.c` 287·613·1300 이
  `catalog_get_representation()` 으로 읽은 뒤 `catalog_add_representation()`(450·1597)으로 쓴다. 즉 **카탈로그
  BTREE_STATS 레코드 포맷을 바꾸면 `UPDATE STATISTICS` 로 제자리 마이그레이션을 할 수 없다** — 옛 포맷 파서를 지우는
  순간 그 데이터베이스는 읽을 수도, 옮길 수도 없다. 포맷 변경의 되돌릴 수 없는 시점을 가르는 사실. **미수정**
- **[storage §2] `Num_page_locks_acquired` 는 락 매니저 카운터가 아니다** (.50, `519cc1a43`, 2026-09-11 실측):
  `PSTAT_LK_NUM_ACQUIRED_ON_PAGES` 가 증가하는 곳은 `page_buffer.c:8018` **`pgbuf_lock_page()`** 한 곳뿐이고,
  VPID 가 버퍼 락 체인에 없어 새로 걸고 `PGBUF_LOCK_HOLDER` 가 될 때 센다 — 사실상 **페이지 첫 접근(버퍼 적재) 횟수**다.
  이름 때문에 트랜잭션 락으로 오해하기 쉽다(`Num_object_locks_*` 가 그쪽). TC `cbrd_20145_1` 의 debug 답안이 27→25 로
  바뀐 것은 이 값이고, 같은 답안의 객체락 카운터는 전부 불변이었다. **미수정**
- **[storage §2] 카탈로그 BTREE_STATS 는 현재 두 레이아웃을 읽는다** (.50, `519cc1a43`): `DISK_REPR` 예약 슬롯(offset 16)이
  `stats_layout` 이고 V0 = 80바이트 32비트, V1 = 120바이트 INT64. 레코드 크기가 `CATALOG_BT_STATS_SIZE_OF(layout)` 로
  런타임에 갈려 카탈로그를 순차로 훑는 코드가 두 크기를 모두 맞춰야 한다. **PR#7957(CBRD-27429)에서 V0 와 버전 표시를
  모두 제거 예정** — 머지되면 이 항목을 "V1 단일, 버전 필드 없음"으로 고쳐 옮긴다.
