## 확인한 사실 (develop)
- **[src-object §3] ALL CLASSES 는 통계를 두 번 쓰고, 두 번째가 언제나 샘플링이었다** (.51, 69ffb9aaf, 2026-11-05):
  - `sm_update_all_statistics ()`(schema_manager.c:4374)가 `stats_update_all_statistics (with_fullscan, …)` 로 모든 클래스의 통계를 쓴 뒤, `update_histogram_for_all_classes (random_seed, …)`(network_interface_cl.c:6327)로 히스토그램을 만든다.
  - 두 번째 단계는 `histogram_info.with_fullscan = false` 고정이다. 그리고 `update_or_drop_histogram_helper ()` 의 전 컬럼 경로(execute_schema.c:4597)가 히스토그램 스캔 뒤 `sm_update_statistics (obj, with_fullscan, &ndv_info)` 로 클래스 통계를 다시 쓴다.
  - 서버 `stats_update_statistics_internal ()` 은 넘겨받은 NDV 를 쓰면서도 B-tree 통계는 `btree_get_stats (…, with_fullscan)`(statistics_sr.c:418)로 다시 재고, `catcls_update_class_stats (…, with_fullscan)`(:467)로 `_db_class.statistics_strategy` 를 쓴다.
  - 그래서 `WITH FULLSCAN` 이 남기는 것은 샘플링 값이다. 실측 pkeys[0]: 테이블 단위 FULLSCAN 200000, ALL CLASSES WITH FULLSCAN 86585 → 81328(실행마다 다름), `statistics_strategy` SAMPLING.
  - 게이트(`statistics_sampling_threshold_pages=1000`, `statistics_sample_pages=2000`)를 켜면 NDV(b 4739751→4795260)와 행 수(4800000→4795260)도 표본 외삽값이 된다.
  - 히스토그램 대상 클래스에서 첫 단계의 결과는 언제나 두 번째 단계에 덮였다(스캔 한 번이 통째로 버려짐).
  - 테이블 단위(`do_update_stats ()`, execute_statement.c)는 사용자 플래그를 넘기고, 헬퍼 한 번으로 끝낸다(헬퍼가 `ER_OBJ_INVALID_ARGUMENTS` 면 `sm_update_statistics ()` 로 대체).
  - **수정됨 — PR#8413 `bb3732625`(미머지)**: ALL CLASSES 를 클래스당 한 번, 요청한 방식으로 처리한다. 통계 전용 단계는 `WITH NO HISTOGRAM` 일 때만 돈다.
- **[src-storage §2] B-tree 샘플링은 리프 5,000장까지만 읽는다 — 그 이하 인덱스는 샘플링이어도 정확값** (.51, 69ffb9aaf, 2026-11-05):
  - `STATS_SAMPLING_LEAFS_MAX 5000`(statistics.h:44). 실측 600K 행(리프 934)에서는 ALL CLASSES 도 (200000,600000) 으로 같았다. 통계 결함의 재현·TC 는 리프가 5,000장을 넘어야 한다.
  - TC 크기 줄이기: 4K 페이지 DB(`--db-page-size=4K --log-page-size=4K`)에 정수 두 열 100만 행이면 리프 약 6,400장(80만 행이면 5,096장). 문자열 키는 리프 공통 접두 압축 때문에 리프가 크게 늘지 않는다(400바이트 키 4만 행이 리프 817장).
- **[src-optimizer §3] `db_histogram.scan_type` 은 처음 만든 방식으로 남았다** (.51, 69ffb9aaf, 2026-11-05):
  - `with_fullscan` 은 행을 만들 때(`smt_add_histogram ()`, schema_template.c:2120)만 쓰이고, 다시 수집할 때 쓰는 `store_one_histogram ()`(histogram_cl.cpp:230)은 `null_frequency`·`histogram_values` 만 고친다.
  - 실측: 샘플링으로 다시 수집해도 'FULL SCAN' 그대로. `histogram_values` 를 쓰는 곳은 이 함수 하나다.
  - **수정됨 — PR#8413(미머지)**: 다시 수집할 때 `with_fullscan` 도 고친다.
- **[src-object §2] `SHOW INDEX` 의 Cardinality 와 `INDEX_CARDINALITY ()` 는 key_pos 와 무관하게 전체 키 수다** (.51, 69ffb9aaf, 2026-11-05):
  - `catalog_get_cardinality ()`(system_catalog.c)는 key_pos 범위만 검사하고 `p_stat_info->keys` 를 돌려준다(분할 클래스는 분할마다 합). 2013-08 `c8eae691e`(CUBRIDSUS-12022 "fix show indexes Cardinality")에서 `pkeys[key_pos]` 를 버렸다.
  - 실측: 인덱스 `(a, b)` 의 seq 1·2 가 모두 4800000(pkeys 는 200000, 4800000).
  - 매뉴얼(`information_fn.rst` INDEX_CARDINALITY)은 key_pos 가 부분 키의 고유값 수를 준다고 적는다 — **문서 불일치, 미수정**. pkeys 를 SQL 로 볼 길이 없어 csql `;info stats` 로만 확인된다.
- **[src-parser] UPDATE STATISTICS 의 옵션은 WITH 하나 뒤 쉼표 목록이다**: `with fullscan, no histogram`(csql_grammar.y `stats_option_list`). `with fullscan with no histogram` 은 문법 오류(-493). 같은 옵션 반복·`NO HISTOGRAM`+`DROP HISTOGRAM` 은 0x10 독 플래그로 거부.

- **[src-query §3 보강] `update_or_drop_histogram_helper ()` 가 히스토그램 행 생성 실패를 성공으로 보고한다 — ALL CLASSES 도 마찬가지** (.51, develop release 2362424f2, 2026-11-05 동적):
  - 기존 §3 항목(에러 경로가 `dump_histogram ()` 의 NO_ERROR 로 덮임)의 실측이다. 다른 트랜잭션이 t3 의 첫 `UPDATE STATISTICS ON t3` 를 커밋하지 않고 잡고 있을 때, lock timeout 3초로 `UPDATE STATISTICS ON t3` 와 `ON ALL CLASSES` 를 돌리면 둘 다 `| ERROR: Failed to dump histogram column: a |` 를 찍고 `Statistics updated successfully` 로 끝난다(히스토그램 없음).
  - 이때 develop ALL CLASSES 의 통계 전용 1단계는 t3 에서 막히지 않았다. 다른 트랜잭션의 미커밋 통계 갱신이 같은 클래스의 통계 갱신을 lock timeout 시키지 않는다(관찰 — 카탈로그 접근 락의 보유 기간은 코드로 확인하지 않음).
  - **수정됨 — PR#8413 `4be33c928`(미머지)**: helper 가 원래 오류를 돌려준다(quiet 면 안내 줄 생략, 호출자는 모두 quiet). 테이블 단위·optimizedb·ALL CLASSES 가 그 오류로 실패한다.

## PR#8413 head 의 사실 (미머지 — 머지되면 §2 로)
- `update_histogram_for_all_classes (with_fullscan, random_seed, skip_mops, n_skip, run_start_msec)`: 클래스마다 `statistics` 진행 이벤트 한 쌍(서버 이벤트 로그 UPDATE_STATISTICS), 제외 클래스와 `ER_OBJ_INVALID_ARGUMENTS` 클래스는 `sm_update_statistics ()`. 이벤트 로그의 `histogram` 단계(#8194, CBRD-27663)는 히스토그램을 만드는 실행에서 더 나오지 않는다.
- `sm_update_all_statistics ()`: 상주 클래스 통계 캐시 재설정은 단계가 끝난 뒤 한 번.
- 시간(SA 4.8M 행, 교대 3회 중앙값): ALL CLASSES WITH FULLSCAN 3.20→2.03초, ALL CLASSES 2.52→1.36초(게이트 켬 2.61→2.08, 1.96→0.86), 통계 전용 대조 경로는 같음.
