# 정소희 — CBRD-28043 (PR#8497 리뷰에서 확인한 코드 사실)

작성: 정소희 (.51) · 기준 리비전 develop `99279799f`(PR#8497 merge-base) · 2026-11-16

- **[src-storage §3] `pgbuf_ordered_fix ()` 는 요청 페이지가 거절·재고정 사이에 해제되면, 풀었던 다른 쥔 페이지를 다시 잡지 않은 채 ER_PB_BAD_PAGEID 를 돌려준다** (.51, 99279799f, 2026-11-16): 다른 페이지를 순서 고정으로 쥔 스레드의 요청은 조건부 래치로 시작하고, 거절되면 순서가 뒤인 쥔 페이지를 푼 뒤(page_buffer.c:13435) 요청 페이지부터 순서대로 다시 잡는 루프(:13570)에서 요청 페이지가 OLD_PAGE_MAYBE_DEALLOCATED 로 해제됐거나(:13601-13626) 파일 테이블 페이지로 재사용됐으면(:13632-13633) `goto exit` 한다 — 남은 쥔 페이지의 watcher 는 pgptr NULL·page_was_unfixed 로 남는다. 호출자는 BAD_PAGEID 만으로 다른 watcher 가 풀렸는지 알 수 없으므로, 이 반환을 "해제된 페이지 — 건너뜀" 으로 다루는 호출자(PR#8497 의 `heap_page_list_fix_next ()`)는 풀린 페이지의 PEEK 레코드를 래치 없이 계속 쓰게 된다. 단위 suite dev4 `unit/storage/page_buffer.ordered_fix_gone_page`(O2·O3 base 재현 — 끼어듦은 대본). develop 에서 같은 조합에 닿는 호출자는 UPDATE/DELETE relocation 의 bestspace 경로(heap_insert_newhome → bestspace::find → allocate_verify_actual_space, heap_file.c:23555·23923 — 정적으로 본 것). 수정 방향: 재고정 루프에서 요청 페이지만 건너뛰고 나머지를 다시 잡은 뒤 BAD_PAGEID(단위 변이 `fix.diff` 로 닫힘 확인). **미수정**(PR#8497 리뷰 코멘트 11-16).
