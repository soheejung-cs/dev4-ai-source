# 정소희-CBRD-27862 — B-tree 노드 탐색의 키 표현·위치 (src/storage, src/object)

기준: (.51, CBRD-27361 헤드 `0efc06bf1` + CBRD-27862 로컬 커밋 `83db0659a`, 2026-11-01). 대상 모듈 노트: `modules/src-storage.md` §1·§3.

## 확인한 사실

- **SHORT·INTEGER·BIGINT 의 인덱스 키 이미지는 원시(native) 바이트다** — `mr_index_writeval_int` 는 `or_put_data (buf, &i, tp_Integer.disksize)`
  로 4바이트를 그대로 쓰고 `mr_index_readval_int` 는 `or_get_data` 로 그대로 읽는다(object_primitive.c:2434·2444; short :2605, bigint :2776 도 같다).
  힙(데이터) 표현의 `OR_GET_INT`(빅엔디언)와 다르다. 인덱스 키 비교 `mr_index_cmpdisk_int` 도 `COPYMEM` 으로 원시 값을 비교한다.
- **leaf 레코드의 키 위치** (btree.c `btree_read_record_without_decompression`): 첫 OID 8 → (고유 인덱스이고 첫 OID slotid 칸에 `BTREE_LEAF_RECORD_CLASS_OID`
  면 클래스 OID 8) → (첫 OID volid 칸에 `BTREE_OID_HAS_MVCC_INSID` 면 8) → (`BTREE_OID_HAS_MVCC_DELID` 면 8) → 키. `BTREE_LEAF_RECORD_OVERFLOW_KEY`
  면 키 자리에 overflow VPID. fence 레코드도 같은 배치로 읽힌다. 레코드 플래그는 첫 OID 의 slotid 칸, MVCC 플래그는 volid 칸(둘 다 `OR_GET_SHORT`).
- **non-leaf 레코드의 키 위치**: 고정부(child pageid 4, volid 2, key_len 2 = `NON_LEAF_RECORD_SIZE` 8, 빅엔디언) 바로 뒤. key_len 음수면 overflow 키.
  non-leaf 키의 도메인은 `btid->nonleaf_key_type`(`btree_generate_prefix_domain` — BIT 만 VARBIT 로 바뀌고 나머지는 key_type 그대로).
- **인덱스 스캔의 검색 키 경계(DOMAIN_KEY_BOUND, CBRD-27583)는 키가 있는 경계마다 항상 만들어진다** — `xasl_generation.c` 의 경계 결정(14580~)이
  같은 도메인 쌍(INT 열 = INT 값)에도 `DOMAIN_COMPARE_DIRECT`(cmp = 그 형의 pr_type, 변환 없음)를 담는다. 따라서 `btree_search_leaf_page`·
  `btree_search_nonleaf_page` 의 `bound` 는 질의의 인덱스 스캔에서 NULL 이 아니고, NULL 은 삽입·삭제·고유 검사 같은 자기 도메인 키 탐색이다.
- **비용 구성(JOB 113 직렬, VTune sw hotspots, CPU 192s)**: `btree_locate_key` 28.5% = leaf 탐색 10.8 + non-leaf 탐색 8.4 + 자식 고정 4.0 + 루트 고정 1.8 +
  unfix 1.8 + 노드 헤더 1.1. 레코드 읽기의 `or_init` 자기 시간(3.8%)은 or_init 자체(포인터 대입뿐, ALWAYS_INLINE)가 아니라 그 직후 레코드 첫 접근의
  캐시 미스가 인라인 구간에 잡힌 것이다.

## 바꾼 것 (CBRD-27862 1단계, 미머지)
- 단일 컬럼 SHORT/INT/BIGINT 인덱스에서 같은 형 검색 키(경계 없음, 또는 DIRECT·같은 형 cmpval·변환 없음)면 두 이진 탐색이 레코드의 키 이미지를 직접 비교한다
  (`btree_integral_search_key_*`, `btree_leaf_record_key_image`, `btree_non_leaf_record_key_image`). 그 밖은 기존 DB_VALUE 경로.
- `btree_search_nonleaf_page` 의 `start_col` 미초기화(§3 에 develop 미반영으로 기록된 UB)를 0 으로 초기화 — 이 브랜치가 머지되면 §3 그 항목을 해소로 바꾼다.

## 확인 못 한 것 (Unknowns)
- DATE·TIME·OID 키의 인덱스 이미지가 원시인지(이번 범위 밖) — `mr_index_writeval_date` 등은 보지 않았다.

## 찾아봤는데 없던 것 (Negative searches)
- `MR_CMP` 는 object_primitive.c 안의 지역 매크로다(헤더에 없음) — btree.c 에서 쓰려면 직접 비교식.
