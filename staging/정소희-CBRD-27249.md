# 정소희 — CBRD-27249 (optimizedb --no-histogram) 환류 대기

작성: 정소희 (.51) · 기준 리비전 upstream/develop `bcd6c5936` (수정 PR#8166 draft) · 2026-10-14

- **[statistics §2] `optimizedb -n <class>` 는 develop `bcd6c5936` 까지 히스토그램을 만들지 않았다** (.51, 2026-10-14): `util_sa.c optimizedb()` 가 `sm_update_statistics(class_mop, STATS_WITH_SAMPLING)` 만 호출하고 이 함수엔 히스토그램 경로가 없다. 전체 경로는 `sm_update_all_statistics` → `update_histogram_for_all_classes` 로 만든다. PR#8166(CBRD-27249)에서 `-n` 도 SQL 단일 클래스 순서(헬퍼 먼저 → `ER_OBJ_INVALID_ARGUMENTS` 면 폴백)로 맞춤. **미수정(머지 전)**.
- **[statistics §3] `UPDATE STATISTICS ON ALL CLASSES` 는 클래스마다 두 번 스캔한다** (.51, `bcd6c5936`, 2026-10-14): `sm_update_all_statistics` 가 서버 `stats_update_all_statistics` 로 전 클래스 통계를 갱신한 뒤 `update_histogram_for_all_classes` 가 클래스마다 `update_or_drop_histogram_helper(DO_HISTOGRAM_CREATE)` 를 부르는데, 헬퍼는 자기 스캔으로 클래스 통계를 다시 쓴다(`do_update_stats` 주석 "refreshes the class statistics itself"). 단일 클래스 SQL 경로는 헬퍼 먼저 돌려 이걸 피한다. 예비 이슈 — 전체 경로도 서버 단계를 건너뛸 수 있는지. **미수정**.
