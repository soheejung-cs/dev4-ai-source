# 정소희-CBRD-27361 — 해시 GROUP BY 병합 테이블의 키 복사 (src/query, src/object)

작성: 정소희 (.51) · 기준 develop `ef2c78cda`(#8196 `309265e6d` 포함) · 2026-11-03. 대상 모듈 노트: `modules/src-query.md` §2·§3, `modules/src-object.md` §2.

## 확인한 사실
- **[src-query §3] SET 열로 GROUP BY 하면 해시 병합이 모든 행을 첫 그룹으로 접는다** (.51, ef2c78cda, 2026-11-03): SET 출력은 행별 해시 집계를 건너뛰어(`QPROC_TPLDESCR_RETRY_SET_TYPE`, query_executor.c:1448) 모든 행이 unsorted list 에 남고, #8196 뒤 `qexec_groupby` 가 그것을 `qexec_gby_hash_merge`(query_executor.c:8626) → `qexec_gby_merge_rows` 로 끝낸다. 새 키는 `qexec_gby_mtable_add`(query_executor.c:6229)가 `DB_NEED_CLEAR` 아니면 얕게 복사해(query_executor.c:6317) SET 키가 읽은 쪽 SETREF 를 같이 가리키고, 그 SETREF 가 다음 행 읽기에서 놓이고 다시 만들어져 모든 키가 같은 SET 이 된다. `select s, count (*) from t group by s` 5행 → `{1,2}` 5(정답 3그룹), `group by i, s` 는 i 가 겹치면 행이 빠진다. ad7a255c5(#8196 직전) 맞음 — 그때 해시 경로는 `qdata_copy_agg_hkey` 가 키를 늘 `pr_copy_value` 로 깊게 복사했다(ad7a255c5 query_aggregate.cpp:3266). 병합 테이블 rewind 는 키 값을 조건 없이 `pr_clear_value` 한다(query_executor.c:6147). 우회 `/*+ NO_HASH_AGGREGATE */`. **미수정** — 동료가 수정 중(권한 방향: SET 계열도 `pr_clone_value`).
- **[src-object §2] SET 의 PEEK 읽기는 별도 SETREF 를 만들고 need_clear 를 세우지 않는다** (.51, ef2c78cda, 2026-11-03): `mr_data_readval_set`(object_primitive.c:7158)의 copy = false 분기는 `set_make_reference ()`(object_primitive.c:7242, Set_Ref_Area)로 SETREF 를 만들어 디스크 비트를 가리키게 하고 `db_make_set` 으로 싣는다 — `DB_NEED_CLEAR`(dbtype.h:81)는 need_clear·압축 문자열만 보므로 '해제할 것 없음' 으로 보인다. 그러나 `pr_clear_value` 는 SET 이면 need_clear 와 상관없이 `set_free`(참조 수 감소)를 부른다(object_primitive.c:1939). 그래서 PEEK 한 SET DB_VALUE 를 얕게 복사해 오래 쓰면 읽은 쪽이 놓은 SETREF 를 가리키게 된다.
