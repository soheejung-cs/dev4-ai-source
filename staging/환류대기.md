# 환류 대기 — 아직 모듈 §2·§3 에 반영하지 않은 검증된 코드 사실

형식: `- **[모듈 §2|§3] 한 줄 주장** (컨테이너, 기준 리비전, 날짜): 근거. 미수정이면 **미수정**.`
하루 1회 `modules/<모듈>.md` 로 옮기고 여기서 지운다(중복 금지). 규약은 `skills/source-learning/SKILL.md`.

- **[src-optimizer §2 / src-object §2] 옵티마이저 히스토그램 읽기는 잠금 조회다** (.51, PR#7900 `1b6e8e3a0` 기준, 2026-09-09 실측):
  `stats_get_histogram` → `db_get_histogram` → `db_find_multi_unique(DB_FETCH_READ)` → `obj_find_multi_attr` →
  클라이언트 `btree_find_unique`(서버 `sbtree_find_unique`가 **S_SELECT_WITH_LOCK 고정**) → 행 S락, 이어서
  `au_fetch_instance_force(..., LC_FETCH_DIRTY_VERSION)` → 또 S락. `_db_histogram`은 `tf_is_catalog_class`(ct_Classes)에
  없어 무잠금 카탈로그 경로도 안 탄다. 그래서 오토커밋 OFF 세션이 `UPDATE STATISTICS`를 커밋하지 않으면 같은 테이블
  SELECT 컴파일이 커밋까지 블록(lockdb: `_db_histogram` 인스턴스 X 보유 / S 대기). 반대로 컴파일만 한 세션의 S락도
  커밋까지 남아 `UPDATE STATISTICS`의 X를 막는다. 수정: CBRD-27369 `348e93909`(`mvcc_satisfies_committed`,
  `LC_FETCH_COMMITTED_VERSION`, `db_get_histogram_committed`) — **PR 반영 여부는 보드 #94 확인**.
- **[src-storage §2] `xbtree_find_unique`의 S_SELECT는 카탈로그 클래스만 무잠금** — `tf_is_catalog_class`면 NULL_LOCK +
  `btree_key_find_unique_version_oid`, 그 외 사용자 클래스는 dirty snapshot + `btree_key_find_and_lock_unique` S_LOCK으로
  **승격**된다(op_type이 S_SELECT여도 잠근다). `need_skip_mvcc_snapshot`에 `_db_user/_db_synonym/_db_histogram`이 있는 이유:
  컴파일 시점 내부 조회가 RR 트랜잭션 스냅샷을 만들지 않게 하려는 것(CBRD-26202 #7180부터) — 히스토그램 읽기 경로를 바꿀 때
  **스냅샷을 새로 만들면 안 된다**는 제약으로 읽는다.
- **[src-transaction §2] 클라이언트 `locator_lock`은 mop에 락이 있으면 fetch 버전을 DIRTY로 강제**하고, NULL_LOCK 요청은
  `ws_is_mop_fetched_with_current_snapshot`(문장마다 `ws_increment_mvcc_snapshot_version`)로 재fetch를 결정한다.
  `xlocator_fetch`는 초기 버전타입이 MVCC일 때만 "NULL_LOCK 인스턴스 fetch는 락 보유 필수" 디버그 assert를 건너뛴다.
- **[src-storage §2] `heap_scancache_start(..., NULL snapshot)` 는 "최신 커밋 버전"이 아니라 최신 물리 버전을 준다** (.51 2026-09-16, PR#7900 리뷰로 확정): `heap_get_visible_version_internal()` 은 snapshot 이 없으면 가시성 검사도 `prev_version_lsa` 추적도 건너뛴다. 커밋 버전이 필요하면 `mvcc_satisfies_committed` 같은 snapshot fn 을 명시해야 한다(`TOO_NEW` → `heap_get_visible_version_from_log`).
- **[src-object §2] 객체계층 유니크 조회의 잠금 두 겹**: `obj_find_multi_attr` → 클라이언트 `btree_find_unique` → 서버 `sbtree_find_unique` 가 **`S_SELECT_WITH_LOCK` 고정**(행 S) + `au_fetch_instance_force(..., LC_FETCH_DIRTY_VERSION)`(다시 S). op_type 을 실어 보내려면 `btree_find_multi_uniques(…, op_type)` 를 써야 한다.
- **[src-object §2] `ws_decache` 는 dirty(미flush) 객체에 쓰면 안 된다** — work_space.c 주석의 명시 규약. 카탈로그 객체를 읽고 버릴 때 `ws_is_dirty()` 먼저 (PR#7900 `a910e8e6e` 에서 실제로 걸림).
- **[src-object §2] `_db_histogram` 스키마 = class_of/key_attr/with_fullscan/null_frequency/histogram_values, 타임스탬프 없음.** 기존 행 재빌드(`store_one_histogram`)는 `null_frequency`·`histogram_values` 만 갱신하고 **`with_fullscan` 은 안 바꾼다**(`sm_add_histogram` 이 `ER_LC_CLASSNAME_EXIST` 로 건너뜀) — 재빌드 여부 신호로 `with_fullscan` 을 쓰면 오판. 신호는 행 chn 또는 `null_frequency`.
- **[src-object §2] `_db_class.statistics_strategy` 는 `db_class`/information_schema 뷰에서 `DECODE(…,0,'SAMPLING',1,'FULLSCAN')` 로 노출** — 비트를 더 실으면 뷰가 NULL 을 낸다(카탈로그 버전 없이 확장 불가).
- **[src-transaction §2] 락 자원 종류는 `LOCK_RESOURCE_INSTANCE/CLASS/ROOT_CLASS` 셋.** 카탈로그는 bit 15(`VIRTUAL_CLASS_DIR_OID_MASK`) 합성 OID 를 `OID_IS_VIRTUAL_CLASS_OF_DIR_OID()` 로 락 매니저가 알아봐 lockdb 에 따로 표시한다(lock_manager.c:5648·10327, msg 15~18·43·45) — 합성 OID 자원을 lockdb 에 이름 붙이는 선례.
- **[src-query §2] `UPDATE STATISTICS`는 XASL 캐시를 무효화하지 않는다** (실측 2026-09-09, PR#7900 빌드): 통계 커밋 뒤 같은
  SQL은 캐시된 구 플랜(iscan card 100)을 그대로 쓰고, `/*+ RECOMPILE */` 또는 서버 재시작 후에만 새 플랜(sscan card 99004).
