- **[src-object §2] NaN 은 `OR_CHECK_SHORT_OVERFLOW` 를 통과해 SMALLINT 좁힘 UB 에 닿는다** (.50, `eb88ab4ea`, 2026-10-23 SA 실측): Linux 의 `string_to_double` 은 `strtod`(porting.h:1022)라 `tp_atof`(object_domain.c:4695)가 `'nan'` 을 NaN 으로 받고, `OR_CHECK_SHORT_OVERFLOW(i)` = `(i) > DB_INT16_MAX || (i) < DB_INT16_MIN`(object_representation.h:119)은 NaN 에 거짓이다 → `CAST('nan' AS SMALLINT)`·`CAST(CAST('nan' AS DOUBLE) AS SMALLINT)` 가 오류 없이 **0**(develop 동치 빌드 `57e11b9d0` 실측). INTEGER·BIGINT 는 `_FROM_FP`(`!(v >= -B && v < B)`)가 NaN 을 오버플로로 본다. strict(COMPARE/OPERAND)는 `modf` 가 NaN 을 걸러 `DOMAIN_INCOMPATIBLE`. 16eb8474d 이전부터 있던 동작. 같은 구멍이 DOUBLE·MONETARY → TIME(`tp_value_convert_double_to_time`·`tp_value_convert_monetary_to_time`, `OR_CHECK_INT_OVERFLOW`)에도 있어 NaN 이 `12:00:0/ AM`(깨진 TIME)으로 나온다(FLOAT → TIME 은 `_FROM_FP` 라 overflow). **PR#8253 이 SMALLINT 실수 검사를 안쪽 꼴로, TIME 두 변환기를 `tp_double_int_overflow` 로 바꿈(미머지) — strict NaN → SMALLINT 는 그 뒤 `DOMAIN_OVERFLOW`.**
