- **[src-object §2] 비-strict 수 → 정수 변환은 범위를 "원래 값" 으로 보고 "반올림한 값" 을 좁힌다** (.52, `b8199438e`, 2026-10-16 단위 실측): `tp_numeric_overflow<DST> (number)` 로 검사한 뒤(object_domain_convert.cpp:359 문자열 원천, :397 수 원천) `ROUND (number)`(:73, `x + .5` / `x - .5`)를 정수로 캐스트한다(:376 `tp_numeric_value<DST>::make (target, ROUND (number))`, :427 `static_cast<target_type> (ROUND (number))`). INTEGER 의 부동소수 검사는 `OR_CHECK_INT_OVERFLOW_FROM_FP`(`v < 2^31`, object_representation.h:138)라 **[2147483647.5, 2^31) 이 검사를 통과하고 반올림 뒤 2^31 이 되어** int 좁힘이 범위를 벗어난다(UB, x86 에서 INT_MIN). :427 의 `OR_CHECK_ASSIGN_OVERFLOW` 가드는 BIGINT 와 FLOAT→INTEGER 에만 걸려 DOUBLE·MONETARY→INTEGER 는 빠진다. SMALLINT 는 `OR_CHECK_SHORT_OVERFLOW`(> 32767)라 해당 없음. 16eb8474d 이전엔 `OR_CHECK_INT_OVERFLOW`(> 2147483647)가 먼저 걸러 OVERFLOW 였다. ✅ 정수 대상 범위 검사는 `trunc (ROUND (number))` 로 — `ROUND (number)` 만 보면 `'-2147483648'`·`'32767'` 같은 정확 경계가 ±0.5 때문에 거절된다(수정 변이로 확인). CAST 경로: `fetch_cast_operand`(fetch_arith_ops.c:293) → `tp_value_cast_with_converter` / `tp_value_cast(_force)` → `tp_value_cast_internal`(object_domain.c:5505) → `tp_value_convert_number`(object_domain_convert.cpp:261). **PR#8253 이 좁히기 직전 `trunc (ROUND (number))` 를 다시 검사하도록 고침(미머지).**
- **[src-object §2] NaN 은 `OR_CHECK_SHORT_OVERFLOW` 를 통과해 SMALLINT 좁힘 UB 에 닿는다** (.50, `eb88ab4ea`, 2026-10-23 SA 실측): Linux 의 `string_to_double` 은 `strtod`(porting.h:1022)라 `tp_atof`(object_domain.c:4695)가 `'nan'` 을 NaN 으로 받고, `OR_CHECK_SHORT_OVERFLOW(i)` = `(i) > DB_INT16_MAX || (i) < DB_INT16_MIN`(object_representation.h:119)은 NaN 에 거짓이다 → `CAST('nan' AS SMALLINT)`·`CAST(CAST('nan' AS DOUBLE) AS SMALLINT)` 가 오류 없이 **0**(develop 동치 빌드 `57e11b9d0` 실측). INTEGER·BIGINT 는 `_FROM_FP`(`!(v >= -B && v < B)`)가 NaN 을 오버플로로 본다. strict(COMPARE/OPERAND)는 `modf` 가 NaN 을 걸러 `DOMAIN_INCOMPATIBLE`. 16eb8474d 이전부터 있던 동작. **PR#8253 이 `tp_numeric_overflow<SHORT>` 의 실수 입력을 `! (v >= DB_INT16_MIN && v <= DB_INT16_MAX)` 로 바꿈(미머지) — strict NaN → SMALLINT 는 그 뒤 `DOMAIN_OVERFLOW`.**
