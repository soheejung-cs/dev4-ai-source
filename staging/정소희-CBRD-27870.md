- **[src-parser §2] 집계 옆 숨은 컬럼을 만드는 두 번째 재작성: SELECT 목록 상관 서브쿼리** — 집계 SELECT 의 SELECT 목록에 상관 서브쿼리가 있으면 `mq_translate_local ()` 이(`mq_has_class_methods_corr_subqueries ()`)
  `mq_rewrite_aggregate_as_derived ()` 로 집계 부분을 파생 테이블로 만들고, 서브쿼리가 읽는 소스 컬럼을 그 파생 테이블의 숨은 컬럼으로 싣는다(rewritten query `select a_?, ?, (select count(a_?) from dual dual) from (select count(...), t?.a from t? t? where ...) t? (a_?, a_?)`).
  의미 검사를 통과하는 것은 외부 컬럼을 집계로 감싼 서브쿼리뿐이다(`(select max(s3.c))`, `(select count(a))`). `(select s3.c from db_root)` 와 분석 함수의 비집계 컬럼(`first_value(c) over ()`)은 "not single valued".
  실측(release SA): `SELECT COUNT(*), (SELECT MAX(s3.c)) FROM s3 WHERE g = 2`(s3 = (1,'g1',1),(2,'g2',2),(1,'g1b',3)) 가 `ad7a255c5` 1·'g2', develop 1·NULL(페이지 배치), `756c19e28` 1·'g2'. `(SELECT COUNT(s3.c))` 는 1 / 0 / 1.
- **[src-query §3] 힙 스캔의 val_list 슬롯 값은 그 행이 스캔의 현재 행일 때만 유효하다** — 슬롯은 속성 캐시의 값을 공유한다(need_clear=0). 압축 없는 문자열은 페이지 안을 가리키고(`is_peeking = scan_id->fixed`, 스캔이 다음 페이지로 가며 unfix),
  압축 문자열은 속성 캐시가 풀어 둔 버퍼와 압축본(SA·SERVER 의 string readval 이 둘 다 할당, compressed_need_clear=1)을 가리키는데, 필터가 다음 행을 읽을 때
  `eval_data_filter () → heap_attrinfo_read_dbvalues_lazy () → heap_attrinfo_read_dbvalues () → heap_attrvalue_read () → heap_attrvalue_transform_to_dbvalue () → pr_clear_value ()` 가 그 둘을 해제한다.
