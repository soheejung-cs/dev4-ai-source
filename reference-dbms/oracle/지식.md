# Oracle 동작 사실 (매뉴얼 절 번호와 함께) — 정소희

- **복합 FK 와 NULL**: 복합 FK 제약은 (a) 부모의 복합 PK/UNIQUE 를 참조하거나 (b) FK 컬럼 중 **하나 이상이 NULL** 이면 만족된다(match none). → NULL 포함 자식 행은 부모가 없다. [SQL Reference 10g R1, §8 constraint "Foreign Key Constraints", 8-14 (PDF p.546)] — PR#7937 리뷰 2026-09-16
- **ALTER INDEX ... COALESCE**: "merge the contents of index blocks where possible to free blocks for reuse". 채움 비율 인자 없음(PCTFREE 는 생성 시 속성). 제한: temporary table 인덱스 불가, IOT 의 PK 인덱스는 `ALTER TABLE ... COALESCE`. `ALTER INDEX ... SHRINK SPACE COMPACT` 와 동등. [SQL Reference 10g R1, §10 ALTER INDEX, 10-90 (p.722) · shrink_clause 10-83 (p.715)] — PR#7899 리뷰 2026-09-16
- **semijoin / antijoin**: 조인 알고리즘이 아니라 **변환(transformation)** 으로 부른다. antijoin = "returns rows from the left side ... for which there are **no corresponding rows on the right side**"; semijoin = "returns rows that match an EXISTS subquery **without duplicating rows from the left side** when multiple rows on the right side satisfy". 제약: **OR 분기 아래 서브쿼리는 변환하지 않는다.** [SQL Reference 10g R1, §9 Joins, p.615] — PR#7991 리뷰 2026-09-22
- **EXISTS 의미론**: "tests for existence of rows in a subquery", Table 6-10 "TRUE if a subquery **returns at least one row**". 1행 조기 종료의 **의미론적** 근거다(실행 서술은 아니다). [SQL Reference 10g R1, §6 Conditions, p.224] — 2026-09-22
- **DDL 은 앞뒤로 암시적 커밋**: "Oracle Database **implicitly commits the current transaction before and after every DDL statement**". 그리고 **`ANALYZE` 가 DDL 목록에 있다**(`ASSOCIATE/DISASSOCIATE STATISTICS` 도). 대상은 그 문이 건드리는 객체가 아니라 **세션의 진행 중 트랜잭션 전체** — 즉 `ANALYZE` 하나가 앞서 쓴 DML 을 같이 커밋한다. [SQL Reference 10g R1, §10 Types of SQL Statements, p.620] — 2026-09-22
- **`ANALYZE` 는 배타 접근을 요구하지 않는다**: "The GRANT, REVOKE, **ANALYZE**, AUDIT, and COMMENT commands **do not require exclusive access**... you can **analyze a table while other users are updating the table**". (`CREATE`/`ALTER`/`DROP` 은 요구한다.) 통계 수집 동시성(CBRD-27369) 설계 근거. [같은 절, p.620] — 2026-09-22
- **옵티마이저 통계의 정식 경로는 `ANALYZE` 가 아니다**: `ANALYZE` 의 통계 절은 "supported **for backward compatibility**... Instead, use the **`DBMS_STATS`** package... the cost-based optimizer will **eventually use only statistics collected by `DBMS_STATS`**". **`DBMS_STATS` 가 암시적 커밋을 하는지는 이 책에 없다 — 미확인**(PL/SQL Packages and Types Reference 소관). [SQL Reference 10g R1, §13 ANALYZE, p.1006] — 2026-09-22
