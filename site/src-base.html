restrack_assert (resource_tracker.hpp) — 릴리스 벤치마크 결과는 자원 수명 변경의 증거가 될 수 없다 (PR#7658)

  • restrack_assert는 resource_tracker.hpp:446에 정의되어 있고 본문 전체가 #if !defined (NDEBUG) ~ #endif(같은 파일 448~457행)로 감싸여 있어 릴리스 빌드에서는 호출부가 통째로 no-op이 된다. (원 메모의 :455 참조는 부정확했고, 95b79e7ed에서 재검증 — 정의 :446, 가드 448~457행. 원 기준: CBRD-27094 @ faf5a3b2a.)
  • 귀결: 릴리스 빌드에서 돌린 벤치마크는 페이지 fix 누락이나 db_private_alloc 해제 누락을 원리상 한 건도 검출하지 못한다. 실제로 PR#7658은 릴리스 TPC-H에서 22/22 질의 결과 바이트가 동일했는데도 디버그 CI에서 abort가 쏟아졌다. 이 계열 버그의 재현·검증은 반드시 디버그 빌드 + CTP로 해야 하며, 릴리스 성능·정합성 수치는 반증이 되지 않는다.
  • 디버그 빌드의 resource tracker는 push_track()/pop_track() 쌍으로 페이지 fix/락 불균형을 pop 시점에 검출한다.
  • 리뷰 체크포인트자원(페이지 fix, private 메모리) 획득/해제 경로를 건드린 변경에 "릴리스에서 정상 동작하고 성능도 동일하다"만 근거로 달려 있으면 불충분하다고 지적하고 디버그 빌드 CTP 결과를 요구할 것.

mht_get_hash_number (memory_hash.c) — DB_VALUE 해시의 문자열 처리

아래 세 항목의 줄 번호는 89722cf4e 기준이다. develop 2d925cb86 에서 language_support.c·object_primitive.c 는 그대로이고
memory_hash.c 만 위쪽에 함수 하나가 늘어 27줄 밀렸다(본문 동일). SERVER·SA·CS 공통 코드.
  • mht_get_hash_number () 는 문자열의 뒤 ASCII 공백(0x20)을 떼고 해시하고, 빈 문자열·공백만 있는 값은 0 을 돌려준다 (.50, 89722cf4e, 2026-10-27 단위 실측): memory_hash.c:2468-2477 루프(주석 "only the trailing ASCII space is ignored"), :2479-2481 hashcode = 0(develop :2495-2508). 기본 ignore_trailing_space=no 의 VARCHAR 비교는 'a'·'a ' 를 다르게 본다 — lang_fastcmp_byte () 가 앞부분이 같으면 길이 차를 돌려주고(language_support.c:5574-5577), 인덱스 키 비교 mr_cmpval_string () 도 같은 기준이다 (object_primitive.c:11416 의 static ti, :11472 QSTR_COMPARE). CHAR 만 비교도 뒤 공백을 무시한다(object_primitive.c:12401-12404). 해시 테이블 버킷으로 쓰면 충돌이 늘 뿐 무해하지만(같음은 비교가 다시 판정), 해시 값의 개수로 고유값을 세는 곳(distinct 추정)에 쓰면 뒤 공백만 다른 VARCHAR 가 접혀 과소가 된다. — 정소희(.50) 2026-10-28

lang_mht2str_byte / mht_2str_pseudo_key — 콜레이션 문자열 해시 (language_support.c:5753, memory_hash.c:183)

  • 콜레이션 문자열 해시는 PJW/ELF 계열이라 상위 니블이 늘 0(사실상 28비트)이고, 자릿수가 같은 정형 문자열이 구조적으로 충돌한다 (.50, 89722cf4e, 2026-10-27 단위 실측): lang_mht2str_byte ()(language_support.c:5753) 의 ADD_TO_HASH(:3240-3250)가 4비트 이동 + 상위 니블 접기, iso88591_bin 은 mht_2str_pseudo_key ()(memory_hash.c:183, 같은 hashpjw). '2015-01-20' = '2025-01-10', 날짜 문자열 4,096일 → 해시 3,809개; 같은 집합을 바이트 FNV 로 해시하면 충돌 0. 해시 테이블엔 성능 문제일 뿐이지만, 표본 해시의 고유 개수로 추정하는 Duj1 식에서는 표본 4,096개 안 충돌 4쌍만으로 고유값 100만 열이 677,357 로 내려간다. — 정소희(.50) 2026-10-28

lang_fastcmp_byte / lang_fastcmp_ko — 이진 콜레이션의 문자열 비교 (language_support.c:5535, :6138)

  • 이진 콜레이션의 비교는 공백을 NUL 과 같은 0 가중치로 본다 (.50, 89722cf4e, 정적 + 2026-10-27 단위 실측): lang_fastcmp_byte () (language_support.c:5535)가 ASCII_SPACE 를 ZERO 로 바꿔 비교한다(:5547-5549·:5557-5559) — utf8_bin·iso88591_bin 에서 'a b' = 'a\0b'. euckr_bin 의 lang_fastcmp_ko ()(:6138)는 ASCII 공백과 EUC 공백 쌍 0xA1A1 을 0 단위로 본다(:6155·:6159). binary 콜레이션 lang_fastcmp_binary () 는 뒤 NUL 만 무시한다(단위 실측). 그래서 "비교의 같음과 맞는 해시" 를 이진 콜레이션에 만들려면 바이트가 아니라 이 0 단위로 섞어야 한다(그렇게 섞은 해시는 반례 탐색에서 utf8_bin VARCHAR 6/18·CHAR 13/9 → 0/0). — 정소희(.50) 2026-10-28
