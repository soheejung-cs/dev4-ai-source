## 1. 모듈 노트 구조 (`modules/src-<dir>.md`)
- **§1 목적·사용처** — 함수별 표: 이름 / 위치(파일:줄) / 한 줄 / 호출처. 설계 계약 문장도 여기.
- **§2 분석** — 검증된 사실. 소제목은 함수/자료구조 이름. 각 항목은 **주장 → 근거(파일:줄·실측) → 리뷰 체크포인트(✅)**.
- **§3 예비 이슈** — 미수정·미반영. 상태가 바뀌면 여기부터 고친다(다른 컨테이너 오판 방지).
- **§4 진행 중** — 컨테이너·브랜치·PR.
모듈 ↔ 컴포넌트 대응은 `claude-workspace/memory/작업-생애주기.md` §0-1 표(`src/parser`→[B], `src/storage`→[G] …).

## 2. "검증된" 의 기준
- 코드에서 **파일:줄** 을 짚었고, 가능하면 **실행으로 확인**했다(lockdb 덤프, 재현 스크립트, 실측치).
- 어느 **프로세스**(SERVER/CS/SA)에서 도는 코드인지 적었다 — 클라이언트 컴파일 결과는 서버로 XASL 만 건너간다.
- **기준 리비전과 컨테이너**를 적었다: `(.51, PR#7900 8dbaf15f5, 2026-09-16)`. 리비전 없는 사실은 낡으면 구분이 안 된다.
- 추측·미확인은 "**미확인**" 을 붙여 적거나 적지 않는다.

## 3. 절차
```
새 발견 → staging/환류대기.md 에 한 줄(형식은 그 파일 머리) →
하루 1회: 해당 modules/<모듈>.md §2·§3 에 옮기고(출처·리비전 유지) 대기소에서 삭제 →
python3 tools/gen_site.py → commit · push
```
- 작업 시작 전 `git -C ~/dev/docs/dev4-ai-source pull --rebase`. 세 컨테이너가 같은 리포에 push 한다.
- 리뷰·구현 중 확인한 사실은 그 자리에서 대기소에 적는다 — 세션 끝에 몰아 적으면 리비전·근거가 빠진다.
- 소스 노트 §3 에 "미수정" 으로 올라간 건은 **고쳐지면 그 항목부터 갱신**한다.

## 4. 적는 문장의 형
- 주장은 **한 줄**, 뒤에 근거. "`heap_scancache_start(..., NULL)` 는 최신 커밋이 아니라 최신 물리 버전을 준다 —
  `heap_get_visible_version_internal()` 이 snapshot 없으면 가시성 검사와 `prev_version_lsa` 추적을 건너뛴다(.51, 8dbaf15f5)."
- 함정은 **어떻게 잘못 판단하게 되는지**까지: "`with_fullscan` 은 기존 행 재빌드 때 갱신되지 않으므로 재빌드 신호로 쓰면 오판".
- 수치는 조건과 함께(테이블 크기, release/debug).
